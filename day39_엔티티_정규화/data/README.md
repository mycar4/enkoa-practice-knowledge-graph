# 트리플에서 개체 연결과 적재까지 이어지는 실습 데이터

현재 교안과 과제는 `kg_` 파일을 사용합니다.  
단위 프로젝트 2의 라이브러리 문서 추출 저장본에서 22행을 골랐습니다.  
원래 주어, 관계, 목적어, 타입과 근거는 수정하지 않았습니다.

| 범위 | 입력 | 전체 범위의 정답 |
|---|---|---|
| 교안과 종합 실습 | `kg_triples.jsonl`: 22트리플, 출현 44건 | `kg_gold.json`: 19개체, 동일쌍 61건 |
| LV1 | `kg_lv1_triples.jsonl`: 8트리플, 출현 16건 | `kg_lv1_gold.json`: 8개체, 동일쌍 15건 |
| LV2 | `kg_lv2_triples.jsonl`: 14트리플, 출현 28건 | `kg_lv2_gold.json`: 14개체, 동일쌍 37건 |

`kg_corpus.jsonl`은 해당 문서 6개의 전문과 URL입니다. 모든 근거가 원문에 존재합니다.  
`kg_catalog.jsonl`은 공식 문서의 API 이름과 URL을 기준으로 만든 프로젝트 개체 목록입니다.  
`kg_alias_review.jsonl`은 각 출현의 문맥과 타입을 대조한 연결 기록입니다.  
교안 02는 교안 01의 쌍 판정으로 그룹을 만들고 파이썬으로 ID를 부여합니다. 기존 개체 목록에서 ID를 고르지 않습니다.
골드는 마지막에 같은 출현들을 올바르게 묶었는지 평가하는 데만 사용합니다.

출현은 토큰 위치가 아니라 **추출 행의 주어 또는 목적어 자리**입니다.  
`t01:object`처럼 행 ID와 역할을 함께 기록하므로 같은 이름의 반복도 추적할 수 있습니다.  
표준 ID를 붙여도 원래 관계와 근거를 덮어쓰지 않습니다.

`fullkg_provenance.json`에 원본 파일의 해시, 행 번호, 내부 트리플 번호와 선정 이유가 있습니다.  
원본 저장 파일에는 모델명과 추출 시각이 없어 특정 모델을 확정하지 않습니다.

과제의 `kg_lv1_pair_review.json`, `kg_lv2_pair_review.json`은 기존 `kg_alias_review.jsonl`을 같은 개체 쌍으로 변환한 입력입니다.
양쪽 출현의 원문 검토 이유와 원본 출현을 보존합니다. 골드는 변환에 사용하지 않습니다.
재생성: `scripts/day39_revision/assignment_pair_data.py`를 실행합니다.
