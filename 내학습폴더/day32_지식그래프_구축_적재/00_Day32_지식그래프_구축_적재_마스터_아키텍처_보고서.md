## 💡 1. WHY (본질과 정의: 왜 대용량 멱등 적재 파이프라인인가?)

### 10초 초등생 비유: "레고 블록 바코드 분류기와 정전 대비 안전 차단기"
1. **무식한 일반 적재의 재앙**:
   - 3,746건의 공시 데이터를 100건쯤 넣다가 네트워크 오류나 정전으로 멈췄을 때, 다시 실행하면 이미 들어간 100건이 또 들어가서 주주와 회사가 2배로 불어납니다(데이터 오염).
2. **멱등성(Idempotency)의 마법**:
   - 모든 노드와 관계에 바코드(고유 Key: `corp_code`, `rcept_no`, `track_id`)를 붙여서 `MERGE`로 적재합니다. 1번 실행하든 100번 다시 돌리든 결과는 언제나 정확히 동일합니다.
3. **배치 청크 트랜잭션 (Chunked Transaction)**:
   - 1만 건을 1개 트랜잭션으로 한꺼번에 넣으면 메모리 부족(OOM)으로 Neo4j 서버가 폭발합니다. 500건씩 끊어서(`Batch Size = 500`) 안전하게 트랜잭션을 커밋합니다.

## 🛠️ 2. HOW: 프로덕션급 대용량 적재 3단계 아키텍처

```text
   [원천 데이터 소스]                   [파이썬 ETL 프로세서]                 [Neo4j 지식그래프]
┌───────────────────────┐            ┌───────────────────────────┐         ┌────────────────────────┐
│ DART 공시 XML (3,746건) │ ── 파싱 ──▶ │ 1. JSON Chunk 분할 (500건) │ ──UNWIND─▶│ (:Company)             │
│ ART 전형 JSON (15개교)  │            │ 2. 멱등 Key 해싱 & 정제   │ ──MERGE──▶│ (:Shareholder)         │
└───────────────────────┘            │ 3. 트랜잭션 커밋 & 롤백 가드│         │ -[:HOLDS_ECONOMIC_...]-▶
                                     └───────────────────────────┘         └────────────────────────┘
```

## 🏢 3. [DART-Trace] 대용량 공시 멱등 적재 명세

- **원천 타겟**: 3,746건 공시 XML 파싱 데이터 (`batch_runs/run_20260228_.../final_graph_instances.json`)
- **적재 핵심 원칙**:
  - `Company`: `corp_code` 기반 멱등 MERGE
  - `Shareholder`: `holder_key` 기반 멱등 MERGE
  - `EvidenceFragment`: `fragment_id` (공시번호 + XPath) 1:1 보존
  - 배치 크기: 500건 단위 트랜잭션 분할 커밋

## 🎨 4. [ART:READY] 전국 미대 요강 대량 통합 적재 명세

- **원천 타겟**: 서울/수도권 15개 대학 120개 전형 요강 구조화 데이터
- **적재 핵심 원칙**:
  - `University`: `univ_code` 기반 멱등 MERGE
  - `AdmissionTrack`: `track_id` (`{univ_code}_{year}_{track_type}`) 복합 고유키 MERGE
  - `PracticalType`: 표준 실기코드 1:1 매핑
  - `ExamSchedule`: `schedule_id` 기반 다대다 관계 안전 결합

## 🏁 6. 최종 완료 판정 기준
1. 1차 적재 후 총 노드/관계 수 카운트.
2. 2차 동일 배치 재적재 수행 후 **순증 노드/관계 수 = 0건 (100% 멱등성 입증)**.
3. 기준 미달 또는 중복 노드 발견 시 즉시 `FAIL` 처리.
