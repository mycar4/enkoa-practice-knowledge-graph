## 1. 개요
대규모 공시 데이터(3,746건) 및 전국 미대 요강 데이터를 지식그래프로 적재할 때 발생하는 서버 부하, 네트워크 단절, 데이터 중복 문제를 원천 방지하는 멱등 청크 ETL(Extract-Transform-Load) 표준 규격을 정의합니다.

## 2. 노드 및 관계 적재 스키마 매핑표

| 도메인 | 노드 레이블 / 관계 타입 | 고유 키 (Unique Business Key) | 멱등 MERGE 절 및 보존 속성 |
| :--- | :--- | :--- | :--- |
| **DART** | `:Company` | `corp_code` | `ON CREATE SET c.name = row.name, c.market_type = row.market_type` |
| **DART** | `:Shareholder` | `holder_key` | `ON CREATE SET s.name = row.name, s.holder_type = row.holder_type` |
| **DART** | `:EvidenceFragment` | `fragment_id` | `ON CREATE SET e.rcept_no = row.rcept_no, e.table_xpath = row.xpath` |
| **DART** | `-[:HOLDS_ECONOMIC_STAKE]->` | `(s, c)` 복합 키 | `ON MATCH/CREATE SET r.stake_ratio = row.ratio, r.base_date = row.date` |
| **ART** | `:University` | `univ_code` | `ON CREATE SET u.name = row.name, u.campus = row.campus` |

## 3. 프로덕션 청크 적재 Cypher 명세

### 1) DART 주주 지분 및 증거 노드 청크 적재 (Chunk Size = 500)
```cypher
UNWIND $batch AS row
MERGE (c:Company {corp_code: row.corp_code})
  ON CREATE SET c.name = row.corp_name, c.market_type = row.market_type
MERGE (s:Shareholder {holder_key: row.holder_key})
  ON CREATE SET s.name = row.holder_name, s.holder_type = row.holder_type
MERGE (s)-[r:HOLDS_ECONOMIC_STAKE]->(c)
  ON CREATE SET r.stake_ratio = row.stake_ratio, r.base_date = row.base_date
MERGE (e:EvidenceFragment {fragment_id: row.fragment_id})
  ON CREATE SET e.rcept_no = row.rcept_no, e.table_xpath = row.table_xpath
MERGE (c)-[:BACKED_BY_EVIDENCE]->(e);
```

### 2) ART:READY 대학 전형 및 실기종목 청크 적재
```cypher
UNWIND $batch AS row
MERGE (u:University {univ_code: row.univ_code})
  ON CREATE SET u.name = row.univ_name, u.campus = row.campus
MERGE (t:AdmissionTrack {track_id: row.track_id})
  ON CREATE SET t.name = row.track_name, t.season = row.season
MERGE (p:PracticalType {code: row.practical_code})
  ON CREATE SET p.name = row.practical_name, p.category = row.category
MERGE (u)-[:OFFERS_TRACK]->(t)
MERGE (t)-[r:REQUIRES_PRACTICAL]->(p)
  ON CREATE SET r.stage = row.stage, r.ratio = row.ratio;
```

## 4. 멱등 검증 및 트랜잭션 안전 수칙
1. **사전 검사 (Pre-Flight Check)**: 디스크 상의 원천 JSON/XML 파일 존재 여부와 체크섬(MD5/SHA256)을 선행 확인한다.
2. **트랜잭션 분할 (Chunk Commit)**: 대용량 데이터는 단일 트랜잭션이 아닌 500~1,000건 단위로 분할하여 OOM 메모리 크래시를 방지한다.
3. **재실행 검증 (Zero-Increase Verification)**: 1회차 적재 완료 후 동일한 데이터셋으로 2회차 적재를 구동했을 때 노드 및 관계의 순증가 수가 반드시 0건이어야 한다.
