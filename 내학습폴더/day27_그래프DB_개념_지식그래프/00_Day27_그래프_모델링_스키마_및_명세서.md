## 📐 1. RDB(테이블) ➔ LPG(속성 그래프) 변환 3대 황금률

RDB의 관계형 데이터나 비정형 JSON을 지식그래프로 모델링할 때 적용하는 3대 변환 규칙입니다:

| 구분 | RDB (관계형 DB) | LPG (속성 그래프 DB) | 우리 도메인 변환 사례 |
|---|---|---|---|
| **규칙 1 (주체)** | 독립적 기본키(PK)를 가진 행(Row) | **고유 식별자(ID)를 가진 노드 (`:Node`)** | `companies` 테이블 행 ➔ `(:Company {corp_code: '00126380'})` |
| **규칙 2 (연결)** | 외래키(FK) 또는 Many-to-Many 조인 테이블 | **방향성을 가진 관계 (`-[ :RELATION ]->`)** | `holdings` 중계 테이블 ➔ `-[:HOLDS_ECONOMIC_STAKE]->` |
| **규칙 3 (속성)** | 행에 속한 일반 컬럼 또는 조인 테이블 컬럼 | **노드 속성 또는 관계 속성 (`{ key: value }`)** | 지분율(`stake_ratio: 7.25`) ➔ 관계 자체에 속성으로 직접 부여 |

## 🏢 2. [DART-Trace] LPG 지식그래프 모델 스키마 명세

### 1) 노드 정의서 (Nodes)
```text
(:Shareholder {
    holder_key: STRING [PK],          // 정규화된 주주 식별키 (예: '국민연금공단')
    name: STRING,                     // 공시 원문 주주명
    holder_type: STRING               // '연기금' | '개인' | '사모펀드' | '일반법인'
})

(:Company {
    corp_code: STRING [PK],           // 8자리 금융감독원 고유법인코드 (예: '00126380')
    name: STRING,                     // 상장사 법인명 (예: '삼성전자')
    is_listed: BOOLEAN                // 유가증권/코스닥 상장 여부
})

(:EvidenceFragment {
    fragment_id: STRING [PK],         // 접수번호 + XPath 해시 (예: '20230515_tbl3_tr5')
    rcept_no: STRING,                 // 14자리 공시 접수번호
    xpath: STRING                     // XML 2D 좌표 경로 (예: 'table[3]/tr[5]')
})
```

### 2) 관계 정의서 (Relationships)
```text
(:Shareholder)-[:HOLDS_ECONOMIC_STAKE {
    stake_ratio: FLOAT,               // 의결권 지분율 (0.0 ~ 100.0)
    shares: INTEGER,                  // 보유 주식 수
    base_date: DATE,                  // 지분 보유 기준일자 (YYYY-MM-DD)
    evidence_level: STRING            // 'curated' | 'reported' | 'candidate'
}]->(:Company)

([HOLDS_ECONOMIC_STAKE])-[:EVIDENCED_BY {
    match_score: FLOAT                // 원문 대조 매칭 신뢰도 (0.0 ~ 1.0)
}]->(:EvidenceFragment)
```

## 🎨 3. [ART:READY] LPG 지식그래프 모델 스키마 명세

### 1) 노드 정의서 (Nodes)
```text
(:University {
    id: STRING [PK],                  // {univ_name}_{campus} (예: 'CAU_SEOUL')
    name: STRING,                     // 대학교명 (예: '중앙대학교')
    campus: STRING                    // 캠퍼스 구분 (예: '서울', '안성')
})

(:Department {
    id: STRING [PK],                  // {dept_name} (예: 'DEPT_SPATIAL_DESIGN')
    name: STRING                      // 모집 단위 학과명 (예: '공간연출전공')
})

(:AdmissionTrack {
    id: STRING [PK],                  // {univ}_{track}_{year} (예: 'CAU_2027_EARLY_PRACTICAL')
    name: STRING,                     // 전형명 (예: '수시 실기형')
    year: INTEGER                     // 모집 학년도 (예: 2027)
})

(:PracticalType {
    id: STRING [PK],                  // {practical_code} (예: 'PRACTICAL_DRAWING')
    name: STRING,                     // 실기 종목명 (예: '소묘')
    category: STRING                  // '순수회화' | '디자인' | '입체조형'
})

(:ExamSchedule {
    id: STRING [PK],                  // {track_id}_{date} (예: 'CAU_2027_PRACTICAL_20261003')
    exam_date: DATE,                  // 실기 고사일 (YYYY-MM-DD, 예: '2026-10-03')
    is_tentative: BOOLEAN             // 일정 확정 여부
})
```

### 2) 관계 정의서 (Relationships)
```text
(:University)-[:OFFERS_TRACK {
    evidence_level: STRING            // 'curated'
}]->(:AdmissionTrack)

(:Department)-[:BELONGS_TO]->(:University)

(:AdmissionTrack)-[:REQUIRES_PRACTICAL {
    stage: INTEGER,                   // 1단계 / 2단계 (예: 1)
    ratio: FLOAT,                     // 실기 반영 비율 % (예: 80.0)
    paper_size: STRING                // 용지 규격 (예: '4절')
}]->(:PracticalType)

(:AdmissionTrack)-[:EXAM_ON {
    stage: INTEGER                    // 1단계
}]->(:ExamSchedule)
```

## 🛡️ 4. 지식그래프 무결성 불변식 (Model Integrity Invariants)

1. **복합키 고유성 불변식**:
   - `University`는 반드시 `name + campus` 복합키로 관리하여 다른 캠퍼스를 1개의 노드로 병합하지 않는다.
2. **관계 방향성 불변식**:
   - `OFFERS_TRACK`은 반드시 `(University) ➔ (AdmissionTrack)` 방향이며, 역방향은 허용하지 않는다.
   - `HOLDS_ECONOMIC_STAKE`는 반드시 `(Shareholder) ➔ (Company)` 방향이다.
3. **근거 등급 보존 불변식**:
   - `evidence_level: 'curated'`는 공식 요강/공시 확정 데이터에만 부여되며, 신규 추정치가 들어와도 덮어쓰여 강등되지 않는다.
