## 💡 1. WHY (본질과 정의: 왜 집계와 인덱스가 필수적인가?)

### 10초 초등생 비유: "백과사전 색인(Index)과 엑셀 계산기(Aggregation)"
1. **인덱스 없는 쿼리 (`AllNodesScan`)**:
   - 3,746건 공시에서 '삼성전자'를 찾기 위해 1페이지부터 끝 페이지까지 1장씩 다 넘겨보는 것과 같습니다. 데이터가 늘어날수록 서버가 멈춥니다.
2. **인덱스 있는 쿼리 (`NodeIndexSeek`)**:
   - 책 맨 뒤 '색인(Index)'에서 'ㅅ' 항목을 보고 단 1초 만에 해당 페이지를 바로 펼치는 것과 같습니다. O(N) 전수 탐색이 O(log N) 고속 탐색으로 바뀝니다.
3. **그래프 집계 (`Aggregation`)**:
   - 삼성전자의 대주주 20명이 가진 지분을 합쳐서(`SUM`) "우호지분이 총 몇 %인가?"를 한 방에 도출하는 핵심 분석 도구입니다.


## 🏢 3. [DART-Trace] 실전 집계 및 인덱스 시나리오

### 1) 서비스 질문 1: 기업별 5% 이상 대주주 총 지분율 합산 (`SUM`)
> *"삼성전자에 대해 5% 이상 지분을 신고한 대주주들의 지분 합계와 평균 지분율을 구하라."*
```cypher
MATCH (s:Shareholder)-[r:HOLDS_ECONOMIC_STAKE]->(c:Company {name: '삼성전자'})
RETURN 
    c.name AS company,
    count(s) AS shareholder_count,
    round(sum(r.stake_ratio), 2) AS total_stake_ratio,
    round(avg(r.stake_ratio), 2) AS average_stake_ratio;
```

### 2) 서비스 질문 2: 인덱스 부착 및 실행 계획 비교 (`PROFILE`)
```cypher
// 고유 인덱스 생성
CREATE CONSTRAINT IF NOT EXISTS FOR (c:Company) REQUIRE c.corp_code IS UNIQUE;

// PROFILE을 통한 실행 계획 검증 (NodeIndexSeek 확인)
PROFILE
MATCH (c:Company {corp_code: '00126380'})
RETURN c.name, c.market_type;
```

## 🎨 4. [ART:READY] 실전 집계 및 랭킹 시나리오

### 1) 서비스 질문 1: 대학별 전형 수 및 평균 실기 비중 집계 (`COUNT`, `AVG`)
> *"대학별로 개설된 실기 전형 개수와 평균 실기 반영 비중을 구하고, 실기 비중이 높은 순으로 랭킹을 매겨라."*
```cypher
MATCH (u:University)-[:OFFERS_TRACK]->(t:AdmissionTrack)-[r:REQUIRES_PRACTICAL]->(p:PracticalType)
RETURN 
    u.name AS university,
    u.campus AS campus,
    count(t) AS total_tracks,
    round(avg(r.ratio), 1) AS avg_practical_ratio,
    max(r.ratio) AS max_practical_ratio
ORDER BY avg_practical_ratio DESC;
```

## 🔬 6. DRY-RUN 검증 계획
1. **DART**: 삼성전자 주주 지분 합산(`SUM`) 및 랭킹 질의 정상 작동 여부 검증.
2. **ART:READY**: 중앙대/한양대 대학별 전형 수(`COUNT`) 및 실기비중 최대치(`MAX`) 집계 검증.
3. **인덱스**: `NodeIndexSeek` 적용 여부 및 DB Hits 대폭 감소 실측.
