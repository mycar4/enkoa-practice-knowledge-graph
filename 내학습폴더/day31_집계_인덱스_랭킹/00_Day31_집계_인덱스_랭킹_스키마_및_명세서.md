## 1. 개요
지식그래프에서 대규모 노드/관계 집합을 빠르게 통계 처리하고, 인덱스를 통해 실시간 조회 응답 속도를 O(1)~O(log N)으로 보장하기 위한 집계 함수 및 인덱스 명세를 정의합니다.

## 2. 인덱스 및 제약조건(Constraint) DDL 명세

### 1) [DART-Trace] 인덱스 및 고유 제약조건
```cypher
// 1. 기업 고유 식별자 제약조건 (Unique Constraint -> 자동 인덱스 생성)
CREATE CONSTRAINT constraint_company_corp_code IF NOT EXISTS
FOR (c:Company) REQUIRE c.corp_code IS UNIQUE;

// 2. 주주 고유 식별자 제약조건
CREATE CONSTRAINT constraint_shareholder_holder_key IF NOT EXISTS
FOR (s:Shareholder) REQUIRE s.holder_key IS UNIQUE;

// 3. 기업명 검색 인덱스 (Index Seek 지원)
CREATE INDEX index_company_name IF NOT EXISTS
FOR (c:Company) ON (c.name);
```

### 2) [ART:READY] 인덱스 및 고유 제약조건
```cypher
// 1. 대학 고유 식별자 제약조건
CREATE CONSTRAINT constraint_university_univ_code IF NOT EXISTS
FOR (u:University) REQUIRE u.univ_code IS UNIQUE;

// 2. 전형 고유 식별자 제약조건
CREATE CONSTRAINT constraint_admission_track_id IF NOT EXISTS
FOR (t:AdmissionTrack) REQUIRE t.track_id IS UNIQUE;

// 3. 실기과목명 검색 인덱스
CREATE INDEX index_practical_type_name IF NOT EXISTS
FOR (p:PracticalType) ON (p.name);
```

## 3. 핵심 실전 집계 및 랭킹 쿼리 템플릿

### Q1. 기업별 5% 이상 대주주 지분 합계 및 평균 집계 (`SUM`, `AVG`, `COUNT`)
```cypher
MATCH (s:Shareholder)-[r:HOLDS_ECONOMIC_STAKE]->(c:Company)
RETURN 
    c.name AS company,
    count(s) AS total_shareholders,
    round(sum(r.stake_ratio), 2) AS total_stake_ratio,
    round(avg(r.stake_ratio), 2) AS avg_stake_ratio,
    max(r.stake_ratio) AS max_stake_ratio
ORDER BY total_stake_ratio DESC;
```

### Q2. 대학별 개설 전형 수 및 평균 실기 비중 랭킹
```cypher
MATCH (u:University)-[:OFFERS_TRACK]->(t:AdmissionTrack)-[r:REQUIRES_PRACTICAL]->(p:PracticalType)
RETURN 
    u.name AS university,
    u.campus AS campus,
    count(DISTINCT t) AS track_count,
    round(avg(r.ratio), 1) AS avg_practical_ratio,
    max(r.ratio) AS max_practical_ratio
ORDER BY avg_practical_ratio DESC, track_count DESC;
```

### Q3. 실행 계획 분석 (`EXPLAIN` vs `PROFILE`)
```cypher
// EXPLAIN: 쿼리를 실제 실행하지 않고 옵티마이저의 계획 트리만 반환
EXPLAIN
MATCH (c:Company {corp_code: $corp_code})
RETURN c.name;

// PROFILE: 쿼리를 실제 실행하며 각 연산자별 실제 DB Hits 및 페이지 캐시 히트 실측
PROFILE
MATCH (c:Company {corp_code: $corp_code})
RETURN c.name;
```

## 4. 성능 튜닝 핵심 원칙
1. **Index Seek 달성**: WHERE 조건절에 사용되는 고유 키(`corp_code`, `univ_code`)는 반드시 인덱스를 생성하여 `AllNodesScan`을 원천 배제할 것.
2. **DISTINCT 집계**: 1개 전형에 여러 실기과목이 연결된 경우 `count(DISTINCT t)`를 적용하여 전형 수 중복 계산을 방지할 것.
3. **LIMIT 조기 적용**: Top-K 랭킹 질의 시 `ORDER BY ... DESC LIMIT K`를 활용하여 메모리 정렬 오버헤드를 최소화할 것.
