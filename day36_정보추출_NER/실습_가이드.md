## 1. 교안_01: 정보 추출과 NER

도입에서 멀티홉·전역 요약 질문이 왜 그래프를 부르는지 세 문단으로 짚고 시작합니다(대단원 아님).

- [ ] **1. 정보 추출(IE)의 큰 그림**: (1-1) IE 의 입력과 출력 · (1-2) IE 4단계(개체 인식 → 스키마 설계 → 관계 추출 → 정규화)와
      오늘 서 있는 자리를 찍어 보는 지도 셀. 이벤트 추출·상호참조 해결은 이름으로만 짚음. 퀴즈.
- [ ] **2. 개체명 인식(NER)**: (2-1) `find` 로 **구간(start·end)** 만들기 + 따라하기(다른 논문 문장) · (2-2) **BIO 태깅** ·
      (2-3) `decode_bio` 로 **태그에서 구간 되살리기**와 **`B-` 가 무엇을 막는지**(같은 유형 개체가 나란히 붙은 경계) ·
      (2-4) 유형 5종(그래프 노드 레이블) · (2-5) 기법 계보(규칙→CRF→BERT→LLM). 퀴즈 2문.
- [ ] **3. 규칙 기반 NER 체험**: (3-1) 정규식 토큰화 + **규칙 기반의 두 축**(패턴은 변이 id `rs9923231` 로 시연, 이름은 사전) + `name2id.json` 표준 사전 · (3-2) **소문자 매칭의 오탐**(`large` 가 유전자로) ·
      (3-3) **약물 상품명에도 같은 함정**(`perform` 이 멘톨, `today` 가 항생제. 사전의 `brand_stopwords` 8개) ·
      (3-4) 대소문자를 지킨 `rule_based_ner`(반환에 `start`·`end` 포함) ·
      (3-5) 못 잡는 것들(`statins`·`Warfarin-related`·공백이 든 이름·`OTC` 약어 충돌)과 한계 정리.
      따라하기(다른 논문에서 오탐 찾기)·퀴즈 4문.

## 2. 교안_02: LLM 기반 NER

모델 호출은 배포본 기준 `.invoke` **10회**입니다(1-1 1 · 2-1 추출 1 · 2-1 확신도 1 · 4-1 배치 6 · 4-2 비교 1).
**열 번 다 과금 호출로 나갑니다.** 그중 2-1 · 4-1 첫 논문 · 4-2 는 프롬프트가 글자까지 같으니, 앞의 답을 변수에 담아 두면 세 번을 아낄 수 있습니다.
정답 노트북은 따라하기와 클론코딩까지 더해 `.invoke` **14회**입니다(위 10회 + 2-1 따라하기 1 · 4-3 따라하기 2 · 클론코딩 1).

- [ ] **1. LLM 으로 개체 뽑기**: (1-1) zero-shot 프롬프트로 규칙 기반이 놓친 `statins`·`Warfarin` 잡기. 퀴즈.
- [ ] **2. 구조화 출력으로 개체 받기**: (2-1) `Entity`·`EntityList` 스키마 + `with_structured_output(EntityList)` →
      `extract_entities`. `type` 은 `Literal` 로 묶고 다섯 유형에 **`Other`** 를 더해 안 맞는 개체를 억지로 뒤집어씌우지 않게 하며, `other_type`(그게 실제로 무엇인지)과 `confidence`(모델의 자기 보고 점수)까지 받는다. 확신도는 깨끗한 문장에서는 위쪽에 몰려 쓸모가 없고 **약어처럼 애매한 자리에서만 떨어진다**는 것을 두 문장으로 확인한다.
      따라하기(다른 논문에서 `Gene` 만 골라내기)·퀴즈.
- [ ] **3. 후처리**: (3-1) 유형 검증(`Other` 가 여기서 걸러진다) → (3-2) 원문 등장 확인 → (3-3) 중복 제거(12→11→9→8, 결함을 일부러 심어 둔 파일).
      3-2 에서는 그 검사가 **진짜 개체를 버리기도 하는** 장면(모델이 `statins` 를 `Statins` 로 고쳐 적을 때)까지 확인.
      따라하기(`ie_followalong_entities.jsonl` 유형별 개수)·퀴즈.
- [ ] **4. 배치 적용과 규칙 대 LLM 비교**: (4-1) 반복문 배치 추출(논문 6편 = `.invoke` 6회)·`Counter` ·
      (4-2) 규칙 기반과 나란히 비교해 **LLM 만 잡은 이름**과 그중 **사전에 없는 이름**(`statins`·`PPIs`·`NSAIDs`·`proton pump inhibitors`)이 왜 문제인지 보고, 두 방식의 역할 분담을 표로 정리 ·
      (4-3) 따라하기(zero-shot 대 few-shot): **형식은 예시 쪽으로 기울지만 유형 배정은 오히려 어긋난** 장면까지 확인. 퀴즈 2문.
- [ ] **🚀 클론코딩**: 추출→유형검증→원문등장→중복제거를 `extract_and_clean(text)` 하나로 묶고, 데모 원문에서 정제 전후 개수를 견주기(교재가 돌렸을 때는 걸러진 것 0건).
- [ ] **참고**: `with_structured_output` 이 형식을 잡는 세 가지 `method`(`json_schema` 기본 · `json_mode` · `function_calling`)와, 실패가 `None` 이 아니라 **예외**로 드러난다는 것.

## 3. 과제 LV1 (기초): 개념 하나씩

데이터: `data/lv1_entities.jsonl`(21개)·`data/lv1_papers.jsonl`(신장·대사 논문 6편). 문제는 다섯 갈래 12문입니다.
구간·BIO(1-1~1-3)와 고정 파일 채점은 결정적, 5-1(라이브 LLM)만 구조·명백 개체로 채점. 모델 호출은 **5-1 에서 1회**.

- [ ] 준비 셀·데이터 살펴보기 실행

      **1-3** 태그에서 구간 되살리기 `restored`(구두점이 붙어 나오는 것이 정상)
- [ ] **2. 개체 스키마 정의**: **2-1** 개체 스키마 `Entity` · **2-2** 개체 목록 스키마 `EntityList`
- [ ] **3. 뽑은 개체 검증**: **3-1** 유형 검증 `valid_type`(20) · **3-2** 스키마 밖 골라내기 `invalid_type`(1) ·
      **3-3** 원문 등장 확인 `present`(18) · **3-4** 환각 개체 `hallucinated`(2, 그중 하나는 다른 논문에는 실재해 코퍼스 전체와 대조하면 못 걸러 낸다)
- [ ] **4. 정리와 집계**: **4-1** 중복 제거 `deduped`(20, 이름이 같고 유형이 다른 개체는 남는다) · **4-2** 유형별 집계 `type_counts`(`Counter`, `Gene` 11)
- [ ] **5. LLM 으로 뽑기**: **5-1** 구조화 출력 추출기 직접 작성 `extract_entities`·`ents`·`names`(모델 호출 1회) · **5-2** 규칙 기반의 한계(서술형)

## 4. 과제 LV2 (응용): 조합

데이터: `data/lv2_entities.jsonl`(19개)·`data/lv2_papers.jsonl`(자가면역 논문 6편). 문제는 네 갈래 10문입니다.
라이브 비교는 방향(규칙<LLM)·구조로 채점. 모델 호출은 3-1 1회 · 4-2 2회 · 4-3 1회로 모두 **4회**입니다(4-1 은 0회).

- [ ] 준비 셀·데이터 살펴보기 실행
- [ ] **1. 정제 파이프라인**: **1-1** 정제 함수 `clean_entities`(15) · **1-2** 제거 사유 `typed`(18)·`present`(16)·`reasons`
- [ ] **2. 배치 집계**: **2-1** 논문별 집계 `per_doc` · **2-2** 유형별 집계 `type_dist`(`Compound` 8)
- [ ] **3. 규칙 기반과 LLM 견주기**: **3-1** 비교 `rule_names`·`llm_names` · **3-2** 역할 분담(서술형)
- [ ] **4. 출력 형식 다루기**: **4-1** 어긋난 응답에서 쓸 수 있는 개체만 건지기 `rows`·`usable`(모델 호출 0회) ·
      **4-2** 유형 제약 없는 프롬프트로 부르기 `free_prompt`(제공된 `make_free_prompt`)·`free_answer`·`out_types` ·
      **4-3** few-shot 프롬프트 조립 `few_prompt`·`few_answer`
- 프롬프트 문구가 곧 실험 조건입니다. **4-2 는 제공 함수를 그대로 쓰고, 4-3 은 두 문자열 사이에 아무것도 넣지 마세요.** 빈 줄 하나가 끼면 예시와 지시 사이가 벌어져 다른 프롬프트가 됩니다.

## 막혔을 때

- 답안 셀의 **힌트**(접근방법·세부구현)를 먼저 펼쳐 본다.
- 그래도 막히면 **정답 노트북**(`정답/`)의 모범답안·해설과 비교한다.
- 모델 답의 **문구는 매번 달라도 정상**입니다. 라이브 LLM 문제의 자가채점은 구조·명백 개체·건수 범위만 봅니다.
- 다만 **모델을 실제로 불렀는지**는 검사합니다(`sent_prompts` 기록). 개체나 답 문자열을 손으로 적어 넣으면 다른 검사를 통과해도 여기서 걸립니다.

- [ ] **학습된 NER 모델**(`dslim/bert-base-NER`)의 출력을 교안_01 4절에서 보고, **과제 LV1 1-3** 에서 직접 읽어 봤다(`entity` 대 `entity_group`, 합치기 전후). **과제 LV2 3-2** 에서는 가중치를 받기 전에 **설정만으로 모델의 유형 목록을 확인**해, 우리 5종을 내는 모델이 없다는 것을 판정했다.
- [ ] 규칙 기반 NER 의 네 가지 한계(미등록어·경계·대소문자·약어 충돌)를 실행으로 각각 확인했다. 대소문자 함정이 **유전자 기호와 약물 상품명 양쪽**에 있다는 것도 봤다.
- [ ] 규칙 기반에 축이 **둘**(이름을 적어 둔 **사전**, 생김새가 정해진 **패턴**)이라는 것을 알고, 변이 id 처럼 사전에 담을 수 없는 개체는 패턴이 맡는다는 것을 실행으로 봤다.
- [ ] LLM 추출·구조화 출력·후처리(유형·원문·중복)를 각각 직접 확인했다.
- [ ] `with_structured_output` 이 **스키마를 요청에 실어 보내고 답을 파싱**하는 방식이며, 어긋난 답은 `None` 이 아니라 **예외**로 드러난다는 것을 안다.
- [ ] **LLM 이 뽑았지만 사전에 없는 이름**이 왜 그래프에 바로 못 들어가는지 설명할 수 있다.
- [ ] 규칙 기반과 LLM 의 **개수 비교는 정확도가 아니라는 것**을 안다. 정답 라벨과 견주는 방법은 이 단원 뒤에서 배운다.
