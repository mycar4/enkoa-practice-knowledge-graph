## 1. 교안_01: 집계·그룹핑·가공 (의료 지식그래프)

데이터: `data/hetionet_*.csv`(Hetionet v1.0 의 CC0 슬라이스). 약물(Compound)·질병(Disease)·유전자(Gene)·
증상(Symptom)·약효분류(PharmacologicClass) 5종과 관계 12종. 데모는 **약물-질병 축**, 따라하기는
**질병-증상 축**으로 갈라 같은 기술을 다른 데이터로 한 번 더 연습합니다.

- [ ] 준비 셀 3개 실행(연결 → 초기화 → 데이터 적재, 3초쯤 걸림) 후 **그래프 살펴보기**.
- [ ] **1. 개수 세기: count**
      - 1-1 무엇을 묶어 셀 것인가(그룹핑 키): 비집계 항이 곧 묶는 기준. 따라하기·퀴즈.
      - 1-2 `count(*)` 와 `count(x)` 는 다른 답을 낸다: `OPTIONAL MATCH` 로 짝 없는 행이 섞이면
        814 대 755 로 갈리고, 그 차이가 치료약 없는 질병 59개다. 퀴즈.
      - 1-3 노드 개수를 셀 때는 `DISTINCT`: 경로가 갈라지면 같은 노드를 여러 번 센다(252 대 91).
        `collect(DISTINCT x)` 도 같은 자리. 퀴즈.
- [ ] **2. 수치 요약: min·max·avg·sum**
      - 2-1 집계한 수를 다시 집계하기: `WITH` 로 넘겨 2단계로. 합계가 관계 수와 같은지 **검산**.
        따라하기·퀴즈.
      - 2-2 **집계가 조용히 틀리는 두 자리**: 같은 물음이라도 **어떤 행을 남기느냐**로 평균이 갈린다
        (9.81 과 5.55. 분자는 같고 분모만 77 대 136). 그리고 집계는 **빠진 값을 건너뛴다**:
        `sum(null)` 은 `null` 이 아니라 `0`.
        그리고 **정수끼리 나누면 버림**(755/77 이 9, `toFloat` 를 쓰면 9.81). 따라하기·퀴즈 3문.
      - 2-3 **평균이 가린 것: 중앙값과 분위수**: `percentileCont(x, 0.5)` 로 중앙값 7,
        `0.9` 로 p90 21. 평균 9.81 이 무엇에 끌려 올라갔는지 숫자로 확인. 퀴즈.
- [ ] **3. 리스트로 모으고 다시 펼치기: collect·UNWIND**
      - 3-1 collect 로 모으기: `size`·`[0..5]`·`collect(DISTINCT x)`.
      - 3-2 UNWIND 로 다시 행으로 펴기: 접었다 펴면 원래 행 수. `UNWIND` 로 관심 항목 여러 개를
        한 번에 조회(대량 적재와 같은 문법). 따라하기·퀴즈.
      - 3-3 **리스트 컴프리헨션** `[x IN 목록 WHERE 조건 | 바꿀식]`, 자리 번호 `목록[0]`·`목록[-1]`,
        범위 밖은 `null`. 퀴즈.
      - 3-4 **패턴 컴프리헨션** `[(a)-[:R]->(b) | b.name]`: 한 행에 목록 여럿, 짝이 없으면 빈 리스트.
        따라하기·퀴즈.
- [ ] **4. 집계한 뒤 거르기: WITH + WHERE**
      - 4-1 집계 결과 조건은 WITH 뒤에(SQL 의 HAVING). 퀴즈.
      - 4-2 **짧게 쓰는 다른 길: `COUNT { }` 서브쿼리**: 4-1 과 같은 답(10)을 `WHERE` 한 줄로.
        `WITH` 집계가 기본이고 이건 짧게 쓰는 자리라는 것까지. 퀴즈.
- [ ] **5. SET 파생 속성**
      - 5-1 집계값을 노드 속성으로 저장. 참/거짓도 저장 가능.
      - 5-2 저장한 값은 낡는다: `REMOVE` 로 정리. 따라하기·퀴즈.
- [ ] **6. 조건별로 값 만들기: CASE**
      - 6-1 조건형 CASE(구간 라벨). 조건 순서·ELSE 주의, CASE 라벨도 그룹핑 키.
      - 6-2 단순형 CASE(`type(r)`): **`TREATS`(병 자체 치료)와 `PALLIATES`(증상 완화)는 다른 말**이라
        뭉뚱그려 세면 안 된다는 것을 편두통 사례(7 대 24)로 확인.
      - 6-3 집계 함수 안에서 계산하기: `sum(CASE ... END)` 로 가중 점수. 따라하기·퀴즈.
- [ ] **7. 내장 함수: 외우지 말고 찾아 쓰기**
      - 7-1 `SHOW FUNCTIONS` 로 **내 데이터베이스의 함수를 직접 세어 본다**(이 판 449개, 갈래 12종).
        이름으로 좁혀 찾는 법(`WHERE name STARTS WITH 'to' AND category = 'Scalar'`)까지.
      - 7-2 갈래별로 하나씩 실행: 문자열(`trim`·`toUpper`·`split`·`replace`·`substring`·`left`·`right`) ·
        수치(`abs`·`ceil`·`floor`·`sign`·`round`) · 리스트(`head`·`last`·`tail`·`reverse`·`range`·`reduce`) ·
        스칼라(`coalesce`·`toInteger`·`toString`·`valueType`·`isEmpty`) · 서술(`all`·`any`·`none`·`single`).
        **`sum` 과 `reduce` 의 차이**(행을 접나, 한 행 안의 리스트를 접나)까지. 따라하기·퀴즈 3문.
      - 7-3 **공식 문서에서 찾는 법**: 갈래별 링크 표와 세 걸음(갈래 정하기 → `SHOW FUNCTIONS` 로
        이름 훑기 → 문서에서 그 함수만, 특히 **빠진 값 처리**를 읽기). 퀴즈 2문.
- [ ] **🚀 응용 클론코딩**: 약효분류별 약물 수와 평균 표적 유전자 수(2단계 집계 파이프라인).

## 2. 교안_02: 인덱스·제약조건·추천 랭킹 (의료 지식그래프)

- [ ] 준비 셀 3개 실행(교안_01 과 같은 그래프라 살펴보기는 생략).
- [ ] **1. 조회를 빠르게: 인덱스**
      - 1-1 인덱스를 만들고 **실행계획으로 재기**: `CREATE INDEX`·`db.awaitIndexes()`·`SHOW INDEXES`.
        유전자 13,113개에서 이름으로 하나 찾는 조회가 `NodeByLabelScan → NodeIndexSeek`,
        **dbHits 26,228 → 3**(약 8,743배). `explain_plan(쿼리, profile=False)` 는 `EXPLAIN`,
        `True` 는 `PROFILE`.
      - 1-2 **레이블을 빼면 인덱스를 못 쓴다**: 같은 조회에서 레이블만 빼면 `AllNodesScan`
        (dbHits 31,082). **인덱스는 레이블마다 따로 걸린다.**
      - 1-3 이 규칙은 **적재 쿼리에도** 적용된다: 관계 200줄에서 레이블을 빼면 dbHits 가
        4,099 → 12,436,099(약 3,034배). **에러는 나지 않고 느려지기만 한다.** 따라하기·퀴즈 4문.
      - 1-4 **속성을 함수로 감싸도 못 쓴다**: `toLower(g.name) = 'alb'` 는 인덱스가 있어도
        dbHits 26,228 그대로(`NodeByLabelScan`). 대소문자 무시 검색이 필요하면 소문자 사본을
        속성으로 저장해 거기에 인덱스를 건다. 퀴즈 2문.
      - 1-5 **인덱스에도 종류가 있다: RANGE 와 TEXT**: 같은 네 조회(같음·앞맞춤·뒷맞춤·부분일치)를
        인덱스 없음 / RANGE / RANGE+TEXT 세 상태에서 재어 표로 대조. **RANGE 는 `ENDS WITH`·
        `CONTAINS` 를 짚지 못한다**(부분일치 13,114 → TEXT 9). 관계 속성 인덱스
        (`FOR ()-[r:타입]-() ON (r.속성)`)도 함께. 따라하기(`Compound` 부분일치)·퀴즈 3문.
- [ ] **2. 중복을 막는 규칙: UNIQUE 제약조건**
      - 2-1 제약을 걸고 확인하기: `SHOW CONSTRAINTS` → `SHOW INDEXES` 의 `owningConstraint` 로
        **제약이 인덱스를 겸한다**는 것을 확인 → 같은 `id` 로 `CREATE` 하면 `ConstraintError` 로 막힘.
      - 2-2 왜 이름이 아니라 `id` 를 열쇠로 삼나: 이름이 겹치는 노드 6건을 데이터로 확인.
      - 2-3 제약은 네 가지(유일성·존재·키·타입) 중 **내 환경에서 무엇이 되는지 직접 걸어 확인**
        (무료판에서는 유일성만). 따라하기·퀴즈 3문.
- [ ] **3. 추천 랭킹: 무엇으로 줄 세울 것인가**
      - 3-1 집계 랭킹의 정석: 가운데 노드를 `count(DISTINCT ...)` 로 세고, 자기 자신은 `WHERE` 로 빼고,
        `ORDER BY 점수 DESC, 보조키`. 고혈압 치료약을 공유 유전자 수로(1위 Carvedilol 14).
      - 3-2 바뀌는 값은 **파라미터로** 넘긴다.
      - 3-3 가운데를 바꾸면 다른 추천: 표적을 많이 공유하는 다른 약물(Simvastatin → Atorvastatin 17 ·
        Lovastatin 16, 셋 다 스타틴 계열). 따라하기(증상을 가운데 둔 질병 유사도)·퀴즈 3문.
      - 3-4 **그룹마다 상위 N 개**: `ORDER BY` 로 줄을 세운 뒤 `collect(...)[0..3]` 으로 접어 자른다.
        `LIMIT` 은 전체에서, 이건 그룹마다. 퀴즈 2문.
      - 3-5 **원점수와 비율은 다른 답을 준다**: 고혈압 랭킹에 전체 표적 수를 붙이면 원점수 3위
        Captopril 의 적중률(0.545)이 1위 Carvedilol(0.538)보다 높다. 그렇다고 비율로만 줄 세우면
        표적이 두세 개뿐인 약이 1.0 으로 올라오므로 **최소 크기 조건**을 함께 둔다.
        따라하기(증상 유사도 비율판)·퀴즈 3문.
- [ ] **🚀 응용 클론코딩**: 질병 하나에 대한 추천 리포트(공유 유전자 수 + 약효분류, OPTIONAL MATCH 두 번).

## 3. 과제 LV1 (기초): 개념 하나씩 (음식 배달, 13문)

데이터: 노트북이 스스로 적재(Customer·Restaurant·Menu·ORDERED{qty,price}). 채점은 전용 DB 실측 스칼라.

- [ ] 준비 셀 3개 실행
- [ ] **1** 전체 메뉴 수(count) · **2** 식당별 메뉴 수(그룹핑) · **3** 메뉴별 총 주문수량(sum)
- [ ] **4** 고객별 평균 결제(avg) · **5** 최고가·최저가(min/max) · **6** 식당 메뉴 목록(collect)
- [ ] **7** 메뉴 목록 모았다 펼치기(collect + UNWIND) · **8** 주문 2건 이상 메뉴(WITH 필터)
- [ ] **8-(2)** 같은 답을 `COUNT { }` 서브쿼리로 한 번 더
- [ ] **9** 총 주문수량 저장(SET) · **10** 식당 분류를 구분 라벨로(CASE 단순형) · **11** 고객 이름 인덱스
- [ ] **12** 평균만 보면 놓치는 것: 중앙값(`percentileCont`)과 **분모**(같은 물음을 `MATCH` 로 한 번,
      `OPTIONAL MATCH` 로 한 번 내어 평균이 갈리고 합계는 같은 것을 확인)
- [ ] **13** 값이 없는 자리를 0 으로 메우기(`coalesce`): 9번이 붙인 `total_ordered` 가 없는 메뉴까지
      전체를 한 행씩 내어, **값이 0 인 것과 속성이 없는 것**이 다르다는 것을 확인(7절 내장 함수를
      과제에서 직접 써 보는 자리)

> 9·11번처럼 **저장·생성**을 요구하는 문항은 자가채점이 파이썬 변수뿐 아니라 **DB 를 다시 조회**해 확인합니다. 
> 값만 화면에 찍고 `SET`·`CREATE INDEX` 를 빠뜨리면 통과하지 못합니다.

## 4. 과제 LV2 (응용): 조합 (음악 차트, 15문)

데이터: 노트북이 스스로 적재(Listener·Song{tag}·Artist·PLAYED{cnt}). `tag` 는 외부 시스템에서
받은 원본 문자열 그대로다(`" 발라드|2021 "`: 한 칸에 두 값 + 앞뒤 공백). 15번에서 다듬어 쓴다.

- [ ] 준비 셀 3개 실행
- [ ] **1** 재생수 상위 3곡(랭킹+LIMIT) · **2** 아티스트별 총 재생수(두 관계 합산)
- [ ] **3** 총 재생 100 이상 곡(HAVING) · **4** 아티스트 곡 목록(collect)
- [ ] **5** 곡 제목 UNIQUE 제약 + 중복 판별 · **6** 2단 WITH 파이프라인 · **7** 평균 재생 35 이상 아티스트(avg 필터)
- [ ] **8-(1)** 아티스트 최고 인기곡 재생수(2단 max) · **8-(2)** 히트곡 표시(SET 파생 속성: DB 재조회로 채점)
- [ ] **9** 재생수 등급별 곡 목록(CASE + collect) · **10** 접기와 펴기 대조(collect + UNWIND)
- [ ] **11** 레이블별 인덱스(EXPLAIN 으로 `NodeIndexSeek` 대 `AllNodesScan` 대조)
- [ ] **12** 제목 일부로 찾을 때는 **TEXT 인덱스**(`NodeIndexScan` 대 `NodeIndexContainsScan`, 종류 확인)
- [ ] **13** 아티스트마다 인기곡 2곡씩(**그룹별 상위 N** = 정렬 후 `collect(...)[0..2]`) +
      같은 목록을 **패턴 컴프리헨션**으로 한 줄에 받기 + **리스트 컴프리헨션**으로 걸러 쓰기
- [ ] **14** 함께 들은 곡 추천: **원점수와 비율**(`toFloat` 없이 나누면 전부 0 이 된다. 두 1위가 갈린다)
- [ ] **15** 한 칸에 든 두 값 갈라 쓰기(`trim`·`split`·`목록[0]`·`toInteger`): `tag` 를 다듬어 장르별로
      집계하고, 발매연도로 최근 곡을 거른다. `trim` 을 빼면 같은 장르가 두 줄로 갈라지고,
      `toInteger` 를 빼면 **에러 없이** 한 행도 안 남는다(7절 문자열 함수를 직접 써 보는 자리)

- [ ] **1. 함께 구매 추천 엔진**: 1단계 상품명 인덱스(멱등) + **실행계획 전후 대조** → 2단계 상품 코드
