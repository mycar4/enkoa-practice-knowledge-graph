이 체크리스트를 위에서부터 따라가면 오늘 실습을 빠짐없이 완주할 수 있습니다.
막히면 각 문제의 **힌트**와 **정답 노트북**(`정답/`)을 참고하세요.

> **Neo4j 는 반드시 "실습 전용" 데이터베이스에 연결하세요.** 각 노트북이 자기 데이터를 스스로 적재해
> 단독 실행됩니다. 교안_02 와 과제 세 권은 서두의 **초기화 셀에서 그래프를 모두 지우고**(`MATCH (n) DETACH DELETE n`)

> 학생용 기본값은 자기 로컬(`bolt://localhost:7687`, 지난 그래프DB 단원에서 설치)이며, 접속 정보는 `.env` 로만

## 1. 교안_01: 경로 탐색 (데모=수도권 전철 실데이터, 따라하기=계좌 송금)

데이터: `data/seoul_subway_stations.csv`(역 659행)와 `data/seoul_subway_edges.csv`(구간 778행)를
`data/load_subway.py` 가 읽어 적재합니다. **자료 출처는 OpenStreetMap contributors (ODbL)** 입니다.
그래프는 역 **659곳**·구간 **778개**·노선 **25가지**이고, 역 노드에 노선 **목록**(`lines`)이,
구간 관계에 그 구간의 노선(`line`)과 두 역 사이 거리(`km`)가 붙어 있습니다. 따라하기용 **계좌 송금** 그래프(계좌 11개·송금 14건)는
노트북 안 시드 셀이 직접 만듭니다.

- [ ] 준비 셀(연결) → **전철 그래프 적재**(5초쯤 걸립니다) → **송금 그래프 적재** → 데이터 살펴보기 실행(실습 전용 DB 확인!).
- [ ] **1. 가변길이 패턴으로 여러 칸 따라가기**
  - [ ] **1-1** 몇 칸 안에 어떤 역이 있나(남부터미널 `*1..2`). 관계에 변수를 붙여 몇 칸을 탔는지 눈으로 보고, `DISTINCT` 유무 대비(7행 대 8행)로 강남이 두 번 나오는 것을 확인한 뒤 그 두 갈래를 펼쳐 본다. `*` 뒤에 올 수 있는 표기(`*2..2`·`*..2`·`*1..`·`*`·`*0..2`)를 표로 훑고, 하한 0 이 출발역을 답에 넣는 것을 대비 셀로 확인. 상한을 열 때 무엇이 먼저 벽에 부딪히는지(무엇을 RETURN 하는가)도 함께 읽기. 따라하기 둘(송금 `*2..2` 대 `*1..3` / 송금 `*0..2`)·퀴즈.
- [ ] **2. 최단 경로**
  - [ ] **2-1** `shortestPath` 로 가장 짧은 길 찾기. 경로 변수 `p =`, 방향 없는 `-[:NEXT_TO]-`(서울역 → 경복궁, 종로3가 환승). 따라하기(송금: 방향을 지킬 때 0갈래 대 무시할 때 4단계)·퀴즈.
  - [ ] **2-2** 최단 경로가 여럿일 때 `allShortestPaths`. 광화문 - 서울역 이 4정거장 **두 갈래**(환승 1번 대 2번)인 것을 확인하고, 구간 속성 `km` 을 더해 **정거장 수는 같아도 거리는 다르다**는 것까지 본다(`shortestPath` 는 거리를 못 본다). 따라하기(송금 1갈래 대 2갈래·구간 금액)·퀴즈.
- [ ] **3. 경로를 해부하고 조건 걸기**
  - [ ] **3-1** `length`·`nodes`·`relationships`: 이동 수·지나는 역·구간 노선(서울역 → 이태원, 삼각지 환승). 따라하기(송금: 계좌 개수 − 1 = 송금 횟수)·퀴즈.
  - [ ] **3-2** 목록에서 값만 뽑기: **리스트 표현식** `[n IN nodes(p) | n.name]`(세로선 앞 `WHERE` 로 걸러 뽑기까지). 따라하기(큰 금액 구간만)·퀴즈.
  - [ ] **3-3** 경로 길이로 줄 세우기(`ORDER BY length(p) DESC, 역` + `LIMIT 13`). `LIMIT` 없이 655줄이 오는 것과 닿지 않는 역 3곳을 확인. `length(p)` 를 `WHERE` 에 직접 걸면 안 되는 이유도 함께 읽기. 따라하기·퀴즈.
  - [ ] **3-4** `all`·`any`·`none` 으로 경로 위 구간에 조건 걸기(도착역 세 곳의 참·거짓 표, `WHERE all` 로 4호선만 타고 닿는 8곳). 따라하기(송금 400만원 이상 고리)·퀴즈.
- [ ] **🚀 응용 클론코딩**: 경로 안내 함수 `guide(start, end)`(환승 여부까지).
- [ ] **참고**: 같은 일을 하는 새 문법(수량자 패턴 `{1,3}`·`SHORTEST`). 읽고 넘어가면 됩니다.

## 2. 교안_02: 다중 조건·WITH 파이프라인 (데모=맛집 추천, 따라하기=캠핑장)

- [ ] 준비 셀 → 초기화 셀 → 맛집 시드 적재 → **캠핑장 시드 적재**(따라하기용) → 데이터 살펴보기 실행.
- [ ] **1. 여러 방식으로 거르기**
  - [ ] **1-1** 목록·부분·접두·접미로 거르기(`IN`·`CONTAINS`·`STARTS WITH`·`ENDS WITH`). 따라하기·퀴즈.
  - [ ] **1-2** 정규식 `=~`(+ `(?i)`)와 목록 파라미터 `IN $names`. 따라하기·퀴즈.
- [ ] **2. 관계의 있고 없음으로 거르기**
  - [ ] **2-1** 한 패턴에 `VISITED`·`LOCATED_IN` 두 단계, 그리고 한 자리에 종류 둘(`-[:A|B]->`). 따라하기(캠핑장 3종 체인)·퀴즈.
  - [ ] **2-2** 패턴 자체를 조건으로: `WHERE (r)<-[:WORKS_AT]-(:Chef)` 와 `NOT`. 따라하기(글램핑 있는 곳·오토캠핑 없는 곳)·퀴즈.
  - [ ] **2-3** `EXISTS { }` 로 넓혀 쓰기(상대 쪽에 조건이 붙을 때). 따라하기·퀴즈.
- [ ] **3. `OPTIONAL MATCH`: 짝이 없어도 빠뜨리지 않기**
  - [ ] **3-1** 짝이 없어도 행 유지(자리는 `null`). 따라하기(모든 캠핑장과 관리자)·퀴즈.
  - [ ] **3-2** **`WHERE` 를 바로 붙이면 걸러지지 않는 함정**을 실행으로 재현하고 `WITH` 로 푼다. 따라하기(관리자 없는 캠핑장)·퀴즈.
  - [ ] **3-3** 두 노드가 닿는지 판별(`p IS NOT NULL`). 따라하기(두 캠퍼)·퀴즈.
  - [ ] **3-4** 화살표가 질문을 바꾼다(`-[:R*]-` vs `-[:R*]->`). 따라하기(화살표 유무 대비)·퀴즈.
- [ ] **4. `WITH` 파이프라인: 단계별로 다듬기**
  - [ ] **4-1** 값 전달·`DISTINCT`·단계 필터, 언제 `AND` 로 충분한가. 따라하기(캠핑장 시설 종류)·퀴즈.
  - [ ] **4-2** 값을 새로 만들어 넘기기(`WITH r, 식 AS 이름`). 표현식에 `AS` 가 필수인 것 확인. 따라하기(1인당 가격)·퀴즈.
  - [ ] **4-3** 중간에서 정렬해 자르기(`WITH ... ORDER BY ... LIMIT`). 자르는 시점 대비. 따라하기(평점 상위 두 곳의 캠퍼)·퀴즈.
- [ ] **5. 정렬과 쪽 넘기기**
  - [ ] **5-1** `ORDER BY` → `SKIP` → `LIMIT`. 따라하기(캠핑장 가격순 2페이지)·퀴즈.
  - [ ] **5-2** 동점이 페이지 경계에 걸리면 페이지가 무너지는 것을 대비 셀로 직접 확인. 따라하기(겹침 0·합치면 6곳)·퀴즈.
- [ ] **🚀 응용 클론코딩**: 추천 질의 조립(평점 상위 두 곳의 셰프 잇기).
- [ ] **참고**: 패턴 안에 조건을 바로 적기(인라인 `WHERE`). 읽고 넘어가면 됩니다.

## 막혔을 때

- 답안 셀의 **힌트**(접근방법·세부구현)를 먼저 펼쳐 본다.
- 그래도 막히면 **정답 노트북**(`정답/`)의 모범답안·해설과 비교한다.
- Cypher 는 **작게 만들어 한 조건씩 확장**하면 디버깅이 쉽습니다(교안_02 의 조립 순서 참고).
- 정렬로 상위를 뽑을 때 순서가 흔들리면 **보조 정렬키**(이름 등)를 하나 더 붙였는지 확인한다. `SKIP` 으로 쪽을 넘길 때는 보조 정렬키가 없으면 행이 겹치거나 빠진다.
- 방향 있는 관계(`TRANSFER`·`ROUTE`·`PREREQ_OF`)는 **화살표를 지켜** 물었는지 확인한다. 화살표를 빼면 거꾸로도 갈 수 있다는 다른 질문이 된다.
- Neo4j 연결 셀이 멈추면 오류 종류를 먼저 본다. `ServiceUnavailable` 이면 실습 전용 인스턴스가 꺼져 있는 것이고, `AuthError` 면 `.env` 의 비밀번호가 다른 것이며, 이 폴더에 `.env` 자체가 없으면 `.env.example` 을 복사해 만든다.
- `rows[0]` 에서 `IndexError` 가 나면 결과가 **빈 목록**이라는 뜻이다. 이름 오타를 먼저 확인하고, 결과가 없을 수 있는 질의라면 `if rows:` 로 확인하거나 `OPTIONAL MATCH` 로 `null` 을 받는다.
- `WHERE` 에 패턴을 적을 때는 **새 변수를 만들 수 없다.** `(r)<-[:WORKS_AT]-(ch:Chef)` 처럼 이름을 붙이면 오류가 난다. 이름이 필요 없으니 `(:Chef)` 로 적고, 상대 쪽에 조건이 붙어야 하면 `EXISTS { }` 를 쓴다.
- `WITH` 에 **표현식을 적을 때는 `AS` 가 필수**다(`WITH r.price * 2 AS 둘이서`). 그리고 `WITH` 에 적지 않은 변수는 다음 절에서 사라지므로 뒤에서 쓸 변수는 함께 적는다.
- `shortestPath` 는 최단 경로를 **한 갈래만** 준다. 같은 길이의 다른 경로가 있는지 확인하려면 `allShortestPaths` 로 세어 본다.
- 교안_01 의 **전철 그래프 적재 셀은 5초 안팎**이 걸린다. 역 659곳·구간 778개를 만드는 중이니 멈춘 것이 아니다. 끝나면 적재한 역·구간 개수가 찍힌다.
- 교안_01 에는 **전체 삭제 초기화 셀이 없다.** 전철·송금 시드 셀이 각각 `:Station`·`:Account` 만 지우고 다시 만들므로 **여러 번 실행해도 그래프가 두 벌로 늘지 않는다.** 결과가 이상하면 두 시드 셀을 다시 실행하면 원래대로 돌아온다.
- 결과가 **수백 줄씩 쏟아지면** 질문이 너무 넓은 것이다. 도착 노드에 이름을 안 박으면 서울역 하나에서만 655줄이 온다. `LIMIT` 으로 위쪽만 받거나(교안_01 3-3), 파이썬에서 `len()` 으로 개수만 세어 본다.
- 가변길이는 **한쪽 끝에 이름을 박고 쓰자.** 도착역 이름만 받을 때는 상한을 열어 둬도 빠르지만, `length(p)` 처럼 **경로 값을 함께 꺼내면** 경로를 전부 만들게 되어 서울역 `*1..12` 가 72,866갈래까지 늘어난다. `any` 조건도 마지막 구간까지 가 봐야 판정되므로 상한을 작게 잡는다. 상한을 정할 수 없는 질문이면 `shortestPath` 로 감싼다.
- `length(p)` 는 **정렬에는 쓰지만 `WHERE` 로 거르지는 않는다.** 이 659역 그래프에서는 1분이 넘도록 끝나지 않는다. 길이로 거르는 일은 다음 시간의 `WITH` 로 한다.
- `shortestPath` 는 **출발과 도착이 같은 행에서 오류**를 낸다. 도착 노드에 이름을 안 박았다면 `WHERE b.name <> '서울역'` 처럼 출발 노드 자신을 먼저 빼야 한다.
- **닿지 못하는 노드는 행 자체가 생기지 않는다.** 서울역에서 재면 655줄뿐이고 제1터미널·제2터미널·탑승동은 빠진다. 없는 것까지 세려면 다음 시간의 `OPTIONAL MATCH` 가 필요하다.
- 전철 자료는 노선별로 이웃한 역을 이어 만든 것이라 **급행·직결 구간이 한 칸으로 이어진 곳**이 있다. 그래서 여기서 세는 정거장 수가 실제 소요 시간과 정확히 같지는 않다. 교안이 고른 역 짝은 이 함정을 피해 골랐다.
- 송금 그래프에서는 **화살표를 빼지 말자.** 돈은 한쪽으로만 흐르므로 `-[:TRANSFER*]->` 로 방향을 지킨다. 화살표를 빼면 내가 보낸 돈과 받은 돈이 한 덩어리로 섞여 다른 질문이 된다.
