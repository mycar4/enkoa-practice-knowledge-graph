## 1. 교안_01: 임베딩 적재와 벡터·전문 인덱스

논문 69편을 `:Document` 노드로 올리고, 임베딩으로 찾고, 개체와 이어 둡니다.
데모 질문은 **약물 대사**, 따라하기 질문은 **우울증 유전 연관**입니다(같은 색인, 다른 질문).

      (1-2) 논문 파일 살펴보기(개념도 `문서를_그래프에_얹기.png`) · (1-3) 임베딩 복습.
      따라하기(세 문장의 코사인 유사도를 손으로 재기)·퀴즈 2문.
- [ ] **2. 임베딩 적재**: (2-1) `db.create.setNodeVectorProperty` 로 `emb` 저장(개념도 `임베딩을_노드속성으로.png`),

- [ ] **3. 벡터 인덱스와 의미 검색**: (3-1) 인덱스 없이 전수 비교해 보고(시간도 잰다)

      (개념도 `벡터인덱스_왜필요한가.png`) ·
      (3-2) **`SEARCH` 절**과 점수의 정체(`(1+코사인)/2`), `LIMIT` 뒤 `WHERE` 는 후필터라는 것과

- [ ] **4. 전문 인덱스: 키워드로 찾기**: (4-1) `CREATE FULLTEXT INDEX`·`db.index.fulltext.queryNodes`,

- [ ] **5. 문서를 개체에 잇기**: (5-1) 사전으로 이름을 찾아 **id 로**(개념도 `이름매칭으로_다리놓기.png`) · (5-2) `MENTIONS` 를 만들고 검산 ·

## 3. 과제 LV1 (기초): 임베딩 적재와 두 가지 인덱스

질문 주제는 **고혈압·심혈관**입니다(교안과 다릅니다). 지식그래프는 올리지 않고 논문만 씁니다.
자가채점은 여러분이 담은 값을 **DB 에서 다시 조회한 결과와 대조**합니다.

문제는 네 갈래로 묶여 있습니다(코딩 10문 + 서술형 1문). 갈래 순서는 교안_01 의 2~4절을 따라가고,
마지막 갈래에서 두 검색을 견줍니다. 지식그래프와 `MENTIONS`(교안_01 1절·5절)는 LV2 에서 다룹니다.

- [ ] 준비 셀·데이터 살펴보기 실행(논문 69편 적재)
- [ ] **1. 임베딩을 노드에 얹기**: (1-1) 임베딩 적재 `loaded` · (1-2) 차원 확인 `dim`
- [ ] **2. 벡터 인덱스와 의미 검색**: (2-1) 벡터 인덱스 `doc_vec`(차원은 `dim` 을 그대로 쓴다) ·
      (2-2) 의미 검색 1위 `top_id`·`top_score` · (2-3) 전수 비교로 확인 `brute_id`·`brute_score` ·
      (2-4) 상위 3편(top_k) `top3` ·
      (2-5) 사전/사후 필터 `post_count`·`pre_count`(거를 속성을 인덱스에 등록해야 사전 필터가 된다)
- [ ] **3. 전문 인덱스와 키워드 검색**: (3-1) 전문 인덱스 `doc_ft` ·
      (3-2) 키워드 검색 `word_ids` 와 검색어 문법 `and_count`·`or_count`·`title_count`
      (`'hypertension'`, 꼬리에 동점 두 편이 있어 그 순서는 안 봅니다) ·
      (3-3) 하이픈 기호 `IL-6` 을 두 방식으로 `loose_count`·`exact_count`
- [ ] **4. 두 검색을 견주기**: (4-1) 서술형(어느 검색을 쓸 것인가)

## 4. 과제 LV2 (응용): 검색에 그래프를 얹기

질문 주제는 **류마티스 관절염**입니다. 준비 셀이 `MENTIONS` 까지 만들어 둡니다.

문제는 네 갈래로 묶여 있습니다(코딩 10문 + 서술형 1문·4항목).

- [ ] 준비 셀·데이터 살펴보기 실행(그래프·논문·임베딩·인덱스·`MENTIONS`)
- [ ] **1. 검색으로 후보 뽑기**: (1-1) 의미 검색 상위 5편 `hits`·`top_ids` ·
      (1-2) 리트리버로 같은 검색 `retriever_ids`
- [ ] **2. 그래프 점수 만들기**: (2-1) 1위 논문이 언급한 개체 `entity_counts` 와 두 걸음 건너간 유전자 `hop_genes` ·
      (2-2) 사전이 안 이은 세 쌍을 `MERGE` 로 잇기 `mention_total` ·
      (2-3) 투영·PageRank `pr_written`·`pr_top` · (2-4) 문서 점수 `scored`(평균, 바닥값 0.15)
- [ ] **3. 그래프로 검색 결과 손보기**: (3-1) 리랭킹 `minmax`·`rerank`·`reranked` 와
      순위가 처음 뒤집히는 비율 `flip_weight`
      (2-4 뒤에는 검색을 다시 돌려 `hits` 를 새로 받는다) ·
      (3-2) 커뮤니티 필터 `anchor_community`·`narrowed`(편수 대신 집합 대조)
- [ ] **4. 찾은 근거로 답 만들기**: (4-1) 근거 문단 `context`(`reranked` 앞 3편) ·
      (4-2) 체인으로 답 받기 `answer` 와 근거 밖 인용 `outside` ·
      (4-3) 서술형 4항목(리랭킹 대 필터, 빠뜨리면 안 될 때, 보고했다 대 입증됐다, 인용 대조의 한계)

## 막힐 때

- **연결 안 됨**: `.env` 의 `NEO4J_URI/USER/PASSWORD` 와 실습 전용 DB 가 켜져 있는지 확인.
- **`Invalid input 'SEARCH'`**: Neo4j 가 2026.01 보다 낮습니다. 올리거나, 그 버전에서는
  `CALL db.index.vector.queryNodes('doc_vec', 3, $q) YIELD node, score` 로 바꿔 쓰세요
  (교안_01 3-2 가 말한 옛 프로시저입니다).
- **`There is no procedure with the name 'gds....' registered for this database instance`**:
  GDS 플러그인이 안 켜져 있습니다. 위 준비 항목을 보세요.
- **초기화 셀이 DB 를 통째로 비웁니다**: 첫 셀의 `MATCH (n) DETACH DELETE n` 은 확인 없이 그 DB 의
  노드를 전부 지우고, 이어서 벡터·전문 인덱스와 GDS 투영까지 내립니다. 앞 일차 실습물이 함께 지워지는 것은
  의도한 동작입니다. 실행 전에 `.env` 의 `NEO4J_URI` 가 **실습 전용 DB** 를 가리키는지 꼭 확인하세요
  (연결 셀이 마지막 줄에 그 주소를 찍어 줍니다).
- **초기화 셀이 `MemoryPoolOutOfMemoryError` 로 멈춤**: 이 문장은 한 트랜잭션에서 전부 지우기 때문에,
  DB 에 쌓인 것이 아주 많으면(적재 셀을 초기화 없이 여러 번 돌린 경우 등) 그 문장 자체가 메모리 한도에
  걸립니다. 그때는 Neo4j Browser 에서 나눠 지운 뒤 노트북을 다시 시작하세요.
  ```cypher
  MATCH ()-[r]->() WITH r LIMIT 50000 DELETE r RETURN count(*)   // 0 이 나올 때까지 반복
  MATCH (n) WITH n LIMIT 50000 DETACH DELETE n RETURN count(*)   // 그다음 노드도 같은 방식으로
  ```
- **벡터 검색 에러(`configured dimensionality of 768, but the provided vector has dimension ...`)**:
  메시지가 가리키는 것은 **질문 벡터**입니다. `embed_texts` 를 거치지 않은 벡터를 넘겼거나,
  임베딩 모델을 바꿔 차원이 달라진 경우입니다. 준비 셀의 `EMBED_DIM` 이 768 인지 보세요.
- **에러는 없는데 검색 결과가 비거나 모자람**: 저장한 임베딩 차원이 인덱스 차원과 다르면 에러 없이
  그 노드가 인덱스에서 빠집니다. 맨 위 초기화 셀이 옛 인덱스를 지우니 거기서부터 다시 실행하세요.
- **`is not an additional property for vector search with filters`**: `SEARCH` 안에 `WHERE` 를 넣었는데
  그 속성을 인덱스에 등록하지 않은 것입니다. 인덱스를 만들 때 `ON n.emb WITH [n.year]` 처럼 거를 속성을
  함께 적어야 합니다(교안_01 3-2). 등록해도 조건은 등호와 `IN` 만 됩니다.
- **투영을 못 만듦(이미 있다고 나옴)**: 맨 위 초기화 셀을 먼저 실행하세요. 그 셀이 남은 투영을 전부
  내립니다. GDS 투영은 이름이 겹치면 다시 만들 수 없습니다.
- **준비 셀이 `OPENAI_API_KEY 를 찾지 못했습니다` 로 멈춤**: `.env` 에 키를 넣고 커널을 재시작한 뒤 준비 셀부터 다시 실행하세요.
- **전문 검색이 0건**: 원문이 **영어**입니다. 한국어 키워드는 문서에 한 글자도 없으니 의미 검색을 쓰세요.
  기호를 찾는데 결과가 이상하게 많다면 하이픈이 쪼개진 것입니다. **따옴표로 묶으세요**(교안_01 4-3).
- **커뮤니티 결과가 매번 조금 다름**: Leiden 에 `randomSeed: 42` 와 `concurrency: 1` 을 주었으므로
  **같은 그래프 위에서 다시 돌리면 배정이 그대로**입니다. 그런데 초기화 셀로 노드를 지우고 다시 적재하면
  Neo4j 가 내부 id 를 새로 매겨 투영에 담기는 순서가 바뀌고, 그러면 묶음 번호와 경계가 갈립니다
  (실측: 다시 적재한 두 실행에서 묶음 수가 171 과 172 로 달랐습니다).
  그래서 자가채점은 **편수를 세지 않고**, 그 자리에서 다시 조회한 결과와 **집합으로 대조**합니다.
  묶음 **번호**로 판단하지 말고 "같은 묶음인가"로 판단하세요.
- **정답 확인**: `정답/` 폴더의 노트북에 모범답안·해설이 있습니다.
