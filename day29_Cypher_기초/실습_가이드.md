# Cypher 기초: 실습 진행 가이드

이 체크리스트를 위에서부터 따라가면 이 단원 실습을 빠짐없이 완주할 수 있습니다.
막히면 각 문제의 **힌트**와 **정답 노트북**(`정답/`)을 참고하세요.

> **이 단원 실습용 데이터베이스를 새로 하나 만들어 쓰세요.** 모든 노트북이 서두에서 연결된 DB 의
> 그래프를 **전부 지우고** 새로 만듭니다. 지난 단원에서 만든 Movies 그래프와 그때 푼 과제 결과가
> 그 DB 에 그대로 남아 있으니, 같은 DB 를 재사용하면 **그게 전부 사라집니다.**
>
> - **권장**: Neo4j Desktop 에서 **새 인스턴스**를 하나 만들고, 그 접속 정보(포트·비밀번호)를
>   `.env` 에 적습니다(노트북에 직접 적지 마세요). 한 인스턴스 안에 데이터베이스만 하나 더 만드는 방식은
>   소용이 없습니다. 이 과정의 준비 셀이 **그 인스턴스의 기본 데이터베이스에 연결**하기 때문입니다.
>   그러니 데이터베이스가 아니라 **인스턴스를 나누세요**.
> - **대안**: 지난 단원 DB(`bolt://localhost:7687`)를 그대로 써도 동작은 합니다. 다만 위에 적은 대로
>   **Movies 그래프와 지난 단원 과제 결과가 지워집니다**. 남겨 둘 생각이면 이 방법은 쓰지 마세요.
>
> Cypher 는 `run_cypher("...")` 헬퍼로 실행합니다. 연결 코드(드라이버)는 뒤 단원에서 배웁니다.
> 지금은 **Cypher 문법**에만 집중하세요. 결과는 **dict 의 리스트**로 돌아오고, 그 뒤는 파이썬으로 다룹니다.

## 1. 교안_01: 만들고 · 찾고 · 고치고 · 지우기

시연 도메인: 스타트업 "노바랩스" 조직(직원·팀·프로젝트). 서두 그림에서 오늘 쓸 그래프 전체를 먼저 봅니다.
따라하기 도메인: 대학 동아리 "캠퍼스라운지"(학생·동아리·행사). 배운 문법을 **다른 데이터에 옮겨 써 보는** 자리라 데이터를 나눠 두었습니다.
두 그래프 모두 시드 셀 바로 앞에 전체 모습 그림이 있습니다(`org-graph-overview.png`·`club-graph-overview.png`).

**1. 생성: 그래프에 데이터 넣기**

- [ ] **1-1. 노드 만들기**: `(:레이블 {속성})` 패턴 해부도(`node-pattern-anatomy.png`).
      **만들고 → 바로 찾아 확인**한 뒤, 같은 일을 **`CREATE ... RETURN`** 한 문장으로 끝내는 쪽과 견줍니다.
      이어서 **속성의 자료형**(정수·실수·문자열·불리언·리스트·날짜) 표와 시연. 여섯 자료형을 한 노드에 넣어
      파이썬 쪽 타입까지 확인하고, **날짜는 `date()` 로 적어야** `.year` 를 꺼내거나
      `duration.between(...)` 으로 기간을 잴 수 있다는 것을 따옴표로 적은 값과 나란히 견줍니다.
      이어서 **레이블 두 개짜리 노드**(`(:Employee:Mentor {...})`)를 직접 만들어, 레이블 하나로 찾아도
      걸리는 것과 둘을 함께 적으면 **둘 다 가진 노드만**(AND) 걸리는 것을 확인합니다.
      따라하기(새 동아리)·퀴즈 3문.
- [ ] **1-2. 관계 만들기**: `MATCH (a),(b) CREATE (a)-[:종류]->(b)` + 관계 패턴 해부도
      (`rel-pattern-anatomy.png`). 따라하기(행사 참가)·퀴즈 2문.
- [ ] **1-3. 관계에 속성 담기**: `-[r:종류 {속성: 값}]->` 로 담고 `r.속성` 으로 꺼내기
      (`rel-property.png`). 따라하기(좌석을 참가 관계에)·퀴즈 2문.
- [ ] **1-4. 노드와 관계를 한 문장으로**: `CREATE (a:A {…})-[:R]->(b:B {…})` 와
      **이미 있는 노드에 쓰면 중복이 생기는 함정**(`create-duplicate-trap.png`).
      따라하기(새 학생·새 동아리)·퀴즈 2문.

**2. 조회: 찾아서 돌려받기**

- [ ] **2-1. MATCH 와 RETURN**: `AS 별칭`(하나·둘) + MATCH 가 잡는 부분 그림(`match-highlight.png`).
      따라하기(행사 이름·상태)·퀴즈 2문.
- [ ] **2-2. 돌려받는 모양 고르기**: `RETURN e` 로 노드를 통째로 받으면 dict 안 dict
      (`return-shapes.png`), 삼중따옴표 여러 줄 쿼리와 `//` 주석. 따라하기(동아리 노드 통째)·퀴즈 2문.

**3. 수정: 만든 것을 고치기**

- [ ] **3-1. SET 으로 값 고치기·더하기**: 있는 값 덮어쓰기 · 없던 속성 새로 붙이기 · 쉼표로 여러 값 ·
      관계 속성도 같은 방법 · 레이블도 `SET e:Manager`(`set-property.png`).
      따라하기(학년 고치고 이메일 붙이기)·퀴즈 3문.
- [ ] **3-2. REMOVE 로 속성·레이블 지우기**: `REMOVE e.phone`(속성) · `REMOVE e:Manager`(레이블) ·
      DELETE 와의 경계표(`remove-property-label.png`). 따라하기(이메일·레이블 떼기)·퀴즈 3문.

**4. 삭제: 잘못 만든 것 되돌리기**

- [ ] **4-1. DELETE**: 무엇에 변수를 붙였는지가 지울 대상(`delete-scope.png`). 관계 없는 노드 ·
      관계만 지우기. 조건 없는 DELETE 안전 경고. 따라하기(참가 취소)·퀴즈 2문.
- [ ] **4-2. DETACH DELETE**: 관계가 붙은 노드는 거부됨(실제 에러 확인) → `DETACH`
      (`detach-delete.png`). 따라하기(자퇴한 학생)·퀴즈 2문.

- [ ] **🚀 응용 클론코딩**: 새 직원 합류 → 관계 속성 붙여 배정 → 그 배정만 `DELETE` 로 되돌리기.

## 2. 교안_02: 조건 · 패턴 · 적재

시연 도메인: 같은 노바랩스 조직(이어서). 따라하기 도메인: 같은 캠퍼스라운지 동아리 그래프.

**1. 조건으로 거르기: WHERE**

- [ ] **1-1. WHERE 와 비교 연산자**: 속성 map 과 무엇이 다른지 눈금으로(`where-vs-propmap.png`).
      이어서 **날짜도 `>=` 로 크기를 비교한다**(시드 프로젝트의 `deadline`). 마감일을 따옴표로만
      적어 두면 **에러 없이 결과만 조용히 빈다**는 함정을 직접 걸어 봅니다.
      비교 데모 2개. 따라하기(3학년 미만)·퀴즈 2문.
- [ ] **1-2. AND·OR 로 조합하기**: 겹치는 부분과 합친 부분(`and-or.png`). 따라하기(OR)·퀴즈 2문.
- [ ] **1-3. NOT 과 IS NULL**: `NOT` 이 `<>` 와 같은 뜻이라는 것과, **속성이 아예 없는 노드는 둘 다에서
      빠지는 함정**(`not-isnull.png`). `IS NULL`·`IS NOT NULL` 로 그 노드를 따로 찾기.
      따라하기(전공 없는 학생)·퀴즈 3문.

**2. 여러 노드를 잇는 패턴**

- [ ] **2-1. 체인과 역방향**: 같은 화살표를 어느 쪽에서 읽느냐(`chain-reverse.png`), 갈라지는 모양.
      따라하기(동아리를 거쳐 행사까지)·퀴즈 2문.
- [ ] **2-2. 공유 패턴**: 가운데 노드를 함께 가리키기(`chain-vs-shared.png`),
      같은 화살표를 두 번 쓰지 않는 규칙과 **그 규칙이 미치는 범위**. 한 `MATCH` 절에 그리면 자기 자신이
      빠지지만 `MATCH` 를 두 절로 쪼개면 자기 자신이 남는 것을 실행으로 견줍니다.
      따라하기(같은 동아리 학생)·퀴즈 3문.

**3. 결과 다듬기**

- [ ] **3-1. 결과는 몇 줄인가**: 행 수는 노드 수가 아니라 화살표 수(`pattern-rows.png`).
      이어서 **쉼표로 패턴을 나란히 적으면 행 수가 곱**이 된다(`MATCH (t:Team), (p:Project)` 는 2 x 2 = 4행).
      쉼표는 잇는 것이 아니라 따로 찾는 것입니다. 따라하기(동아리 이름 세기)·퀴즈 2문.
- [ ] **3-2. DISTINCT 로 되풀이 접기**: 3-1 에서 파이썬 집합으로 하던 일을 Cypher 가 대신한다
      (`distinct.png`). `RETURN DISTINCT` 만 쓴다(`WITH DISTINCT` 는 다음 단원).
      따라하기·퀴즈 2문.
- [ ] **3-3. ORDER BY 와 LIMIT**: 줄을 세우고 위에서 몇 개만(`order-limit.png`).
      동점이 있으면 보조 정렬키가 필요한 이유. 따라하기·퀴즈 3문.

**4. 멱등 적재: MERGE**

- [ ] **4-1. 노드와 관계를 MERGE 로**: 노드 멱등 · CREATE vs MERGE 중복(`create-vs-merge-flow.png`) ·
      관계 MERGE. 따라하기(같은 등록 두 번)·퀴즈 3문.
- [ ] **4-2. MERGE 가 보는 '같은 것'**: 속성을 다르게 적었을 때의 함정
      (`merge-partial-match-trap.png`)과 **관계 속성을 MERGE 에 적으면 화살표가 늘어나는 이유**.
      따라하기(이미 있는 동아리)·퀴즈 2문.
- [ ] **4-3. ON CREATE SET 과 ON MATCH SET**: 같은 MERGE 문이 **처음 실행될 때와 두 번째 실행될 때**
      다른 일을 하게 만든다(`on-create-match-set.png`). 따라하기·퀴즈 3문.

**5. 파이썬 값을 쿼리에 넘기기**

- [ ] `$이름` 자리표시자와 `run_cypher(..., 이름=값)`, 이어 붙이면 깨지는 이유

## 3. 과제 LV1 (기초): 개념 하나씩 (23문)

도메인: 카페 "달빛" 메뉴(음료·재료·분류). 채점은 전용 DB 위 **결정적 결과**.

- [ ] 준비 셀 3개·스키마 그림·데이터 살펴보기 실행
- [ ] **1** CREATE 노드 · **2** CREATE 관계
- [ ] **3** MATCH 레이블(전체) · **4** MATCH 속성(특정 하나)
- [ ] **5** WHERE 비교(`>=`) · **6** WHERE AND · **7** WHERE OR
- [ ] **8** 관계 패턴(커피 분류 음료) · **9** 관계 패턴(우유가 들어가는 음료)
- [ ] **10** RETURN 두 별칭
- [ ] **11** MERGE 노드(멱등) · **12** MERGE 관계(멱등)
- [ ] **13** 관계 속성 담기(`-[r:HAS_INGREDIENT {amount: 18}]->` + `CREATE ... RETURN`)
- [ ] **14** 관계만 지우기(`DELETE r`, 노드는 남긴다) · **15** 노드 지우기(`DETACH DELETE`)
- [ ] **16** 값이 비어 있는 음료 찾기(`IS NULL`)
- [ ] **17** 빠진 값 채우고 표시 붙이기(`SET` 속성·레이블) · **18** 표기 지우기(`REMOVE` 속성·레이블)
- [ ] **19** 아이스 음료가 있는 분류(`RETURN DISTINCT`)
- [ ] **20** 가장 비싼 음료 3종(`ORDER BY` 와 `LIMIT`)
- [ ] **21** 아이스가 아닌 음료, 그리고 빠진 한 잔(`NOT` 과 `IS NULL`)
- [ ] **22** 새 음료와 새 분류를 한 문장으로(`CREATE (a)-[:R]->(b)`)
- [ ] **23** 자료형을 갖춰 넣고 날짜로 찾기(실수·불리언·`date()` + `WHERE launched >= date(...)`)

> **3·5·7번은 1번을, 8번은 2번을 먼저 풀어야** 결과가 맞습니다(1번에서 만든 바닐라라떼가 목록·조건에 걸리고, 2번에서 이은 커피 분류도 결과에 들어갑니다).
> **11·12번**은 여러분이 쓴 쿼리를 문자열 변수(`merge_q`·`rel_merge_q`)에 담아 두면
> **자가채점 셀이 그 쿼리를 한 번 더 실행**해 멱등인지 직접 확인합니다.
>
> **`CREATE` 를 쓰는 1·2·13번의 답안 셀은 한 번만 실행하세요.** 두 번 실행하면 같은 음료·관계가 두 개가 되어
> 채점이 계속 떨어집니다. 그렇게 됐다면 **맨 위 초기화 셀과 시드 셀부터 다시 실행**한 뒤 1번부터 한 번씩만
> 풀면 됩니다.
>
> **14·15번은 13번까지 푼 뒤에 번호 순서대로** 푸세요. 앞에서 만든 바닐라라떼를 지우는 문제라
> 먼저 풀면 1·2·13번 채점이 떨어집니다. 14번에 `DETACH DELETE` 를 쓰면 노드까지 사라져
> 14번 자체가 떨어집니다(그 문제는 **관계만** 지우는 문제입니다). 16번부터는 시드 음료와 11번의
> 카푸치노만 쓰므로 바닐라라떼가 없어도 됩니다.
>
> **17·18번은 그래프의 값을 고칩니다.** 그래서 그 뒤에 앞 문제(3·5·7·10번 등)의 자가채점 셀을
> 다시 실행하면 결과가 달라져 떨어질 수 있습니다. 한 번 통과한 문제는 다시 돌리지 않아도 됩니다.
>
> **20번은 파이썬으로 정렬해 자르면 안 됩니다.** 쿼리를 문자열 변수(`top3_q`)에 담아 두면
> 자가채점 셀이 그 문장을 한 번 더 실행해 `ORDER BY`·`LIMIT` 을 실제로 썼는지 확인합니다.
> **19번도 파이썬 집합이 아니라 Cypher `DISTINCT`** 로 중복을 없애야 합니다.
>
> **22번은 음료도 분류도 아직 없는 상황**이라 `MATCH` 로 잡을 것이 없습니다. 화살표 양 끝에 노드 패턴을
> 그대로 그려 한 문장으로 만드세요. 쿼리를 문자열 변수(`menu_q`)에 담아 두면 자가채점이 그 문장을 읽어
> `MATCH` 없이 `CREATE` 하나로 끝났는지 확인합니다. 이 답안 셀도 **한 번만** 실행하세요.

도메인: 피트니스 센터 "코어짐"(회원·수업·강사).

- [ ] 준비 셀 3개·스키마 그림·데이터 살펴보기 실행
- [ ] **1** 다단 패턴(회원→수업→강사) · **2** 역방향 패턴(강사←수업←회원)
- [ ] **3** WHERE + 패턴(중급 수강생) · **4** 다단 + WHERE(초급 수강생)
- [ ] **5** 공유 패턴(함께 듣는 수업)
- [ ] **6** MERGE 신규 등록(노드·관계: 채점이 재실행해 멱등 확인)
- [ ] **7** 관계 속성 담아 등록(`CREATE … RETURN` 으로 `subin_attend` 에 담기)
- [ ] **8** 관계 속성 조건 + 다단 패턴(`WHERE r.times >= 3` 로 걸러 수업·강사까지)
- [ ] **9** 중급이 아닌 수업과 그 강사(`NOT` + 다단 패턴)
- [ ] **10** 중급 수업을 듣는 회원, 중복 없이(`RETURN DISTINCT`)
- [ ] **11** 가장 오래 다닌 수강 3건(`ORDER BY`·`LIMIT` + `IS NOT NULL`)
- [ ] **12** 새 수업 등록에 처음·재확인 표시 남기기(`ON CREATE SET`·`ON MATCH SET`)
- [ ] **13** 수업 목록을 한 쿼리로 적재하기(`$이름` 자리표시자 + `MERGE`)

> 한 회원이 조건에 맞는 수업을 여러 개 들으면 결과에 **여러 번** 나올 수 있습니다(패턴 곱).
> 3번은 파이썬 **집합(set)**으로 중복을 없애 비교하고, **10번은 Cypher `DISTINCT`** 로 없앱니다.
> 같은 문제를 어디서 푸느냐의 차이를 견줘 보세요.
> 11번도 파이썬 정렬이 아니라 쿼리 안의 `ORDER BY`·`LIMIT` 으로 풀어야 합니다(채점이 재실행해 확인).
>
> **6·7번은 그래프에 회원·관계를 더하는 문제라 맨 마지막에 있습니다.** 앞 문제부터 순서대로 푸세요.
> 6번을 먼저 풀면 새 회원이 4번 결과에 섞여 4번 채점이 떨어집니다.
> 7번 답안 셀은 `CREATE` 라 **한 번만** 실행하세요. 8번은 7번이 만든 관계를 조회합니다.
> 8번 조회에서 하타요가 수강 관계가 빠지는 것은 정상입니다. 그 관계에는 `times` 속성이 없어
> 비교가 성립하지 않기 때문입니다.
>
> **13번의 이름 하나에는 작은따옴표가 들어 있습니다**(`Rock'n'Roll 스피닝`). 그래서 값을 문자열에
> 이어 붙이면 실제로 `CypherSyntaxError` 가 납니다. 자리표시자를 써야 통과합니다.
>
> **12번은 같은 문장을 두 번 실행해야** `opened`(첫 실행)와 `checked`(두 번째 실행)가 둘 다 채워집니다.
> `MERGE` 패턴에는 **식별 속성 `name` 만** 두세요. 다른 값까지 적으면 값이 달라질 때마다 노드가 새로 생깁니다.
> **13번은 값을 문자열에 이어 붙이지 마세요.** 쿼리에는 `$name` 자리표시자를 두고 값은
> `run_cypher(쿼리, name=값)` 으로 넘깁니다(자리표시자 이름과 인자 이름이 같아야 이어집니다).
> 13번은 12번이 만든 모닝필라테스를 목록에 포함하므로 **12번을 먼저** 푸세요.

## 막혔을 때

- 답안 셀의 **힌트**(접근방법·세부구현)를 먼저 펼쳐 본다.
- 그래도 막히면 **정답 노트북**(`정답/`)의 모범답안·해설과 비교한다.
- 결과 순서는 정해져 있지 않으니, 파이썬에서 **정렬하거나 집합**으로 비교합니다.

### 에러 메시지별 대처

| 증상 | 무엇이 잘못됐나 | 무엇을 하면 되나 |
|---|---|---|
| `ServiceUnavailable` / 연결 시도가 오래 걸림 | DB 가 꺼져 있거나 `NEO4J_URI` 의 포트가 다르다 | Neo4j Desktop 에서 그 인스턴스를 **시작**하고, `.env` 의 포트를 인스턴스 화면의 Bolt 포트와 맞춘다 |
| `AuthError` / `Unauthorized` | 아이디·비밀번호가 다르다 | `.env` 의 `NEO4J_USER`·`NEO4J_PASSWORD` 를 그 인스턴스 값으로 고친다 |
| `CypherSyntaxError` | Cypher 문장의 모양이 틀렸다 | 메시지의 `(line n, column m)` 이 가리키는 자리를 본다. 대개 괄호·중괄호 짝, 화살표(`-[:R]->`)의 하이픈, 문자열 작은따옴표가 빠진 것이다 |
| `NameError` | 답안 셀의 변수 이름이 지문과 다르거나, **결과를 변수에 담지 않고 `print` 만** 했다 | 지문에 **볼드로 적힌 변수명**을 그대로 쓰고, `변수 = run_cypher(...)` 로 **담은 뒤** 출력한다 |
| `KeyError` | `RETURN` 의 별칭과 파이썬에서 꺼내는 키가 다르다 | `RETURN d.name AS name` 이면 `row['name']` 이다. 지문의 별칭을 그대로 쓴다 |
| 에러는 없는데 결과가 **빈 리스트** | 패턴이 그래프에 없다 | 1) 레이블 철자(`Drink`·`Member`·`Spot`) 2) **화살표 방향** 3) 그 노드를 아직 안 만든 것은 아닌지, 이 순서로 의심한다 |
| 자가채점이 계속 같은 자리에서 실패 | 앞선 `CREATE` 답안 셀을 여러 번 실행해 데이터가 늘었다 | **맨 위 초기화 셀과 시드 셀부터 다시 실행**한 뒤 1번부터 한 번씩만 푼다 |
