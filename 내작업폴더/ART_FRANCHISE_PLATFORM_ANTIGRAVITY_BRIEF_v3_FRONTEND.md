## 0. 이 문서가 나온 배경

`franchise/web/{bo,co,fo}`에 1차로 만들어진 화면(순수 HTML/CSS/JS, 프레임워크 없음)을
검토하던 중, 세 포털 모두 **"시각적 완성도"와 "앱 수준의 인터랙티브함"을 둘 다 최고
수준으로** 요구한다는 게 확인됐다. 아직 실제 디자인 작업 전(기능 검증용 초안 단계)이라
**지금이 기술스택을 바꾸는 데 가장 비용이 적게 드는 시점**이다 - 디자인/기능을 다 만든
뒤에 바꾸면 사실상 전체 재작업이 된다.

## 1. 프론트엔드 기술스택 전환 (필수)

### 1.1 기존 방식의 문제
현재 `franchise/web/bo`, `co`, `fo`는 프레임워크 없이 순수 HTML/CSS/JS로 작성돼 있다.
정적인 화면 위주라면 문제없지만, 요구사항이 다음과 같이 확장되면 DOM을 손으로
관리하는 바닐라 JS는 코드가 급격히 꼬이고 버그가 늘어난다:
- 실시간 갱신(출결/결제 알림 등)
- 여러 화면·컴포넌트가 상태를 공유하며 즉각 반응하는 인터랙션
- 복잡한 필터/검색/드래그앤드롭(수강 일정 편성 등)

이런 상태 관리 복잡도는 "퀄리티"에도 직접 영향을 준다 - 화면 깜빡임, 갱신 누락, 미묘한
동기화 버그로 나타나기 쉽다.

### 1.2 결정: React + Vite로 전환
- 세 포털(BO/CO/FO) 모두 **React + Vite** 기반 SPA로 재작성한다.
- Vite는 빌드 도구일 뿐이라 최종 산출물은 정적 파일(HTML/CSS/JS 번들)이다 - 아래
  2절의 Vercel 서브도메인 배포 구조와 그대로 호환된다.
- Next.js 등 서버사이드 렌더링 프레임워크는 **채택하지 않는다** - 세 포털 모두 로그인
  이후에만 접근하는 내부 대시보드라 SEO 이점이 없고, 불필요한 서버 인프라 복잡도만
  늘어난다.
- 기존 `franchise/web/*`의 바닐라 코드는 화면 구성/기능 목록을 확인하는 **참고 자료로만
  남겨두고, 컴포넌트 코드를 그대로 옮기지 말고 새로 작성**한다(바닐라 DOM 조작 코드를
  React 컴포넌트에 억지로 이식하면 안티패턴이 된다).

### 1.3 작업 순서 (디자인 시스템 먼저, 화면은 그다음)
1. **공통 디자인 시스템/컴포넌트 라이브러리부터 먼저 확정**한다 - 색상 토큰, 타이포그래피,
   버튼/카드/모달/폼 등 공통 컴포넌트를 BO/CO/FO 세 포털이 공유하도록 먼저 만들고,
   그 위에서 각 포털 화면을 조립한다. (세 포털이 각자 다른 디자인 언어로 따로 만들어지는
   것을 방지)
2. 상태 관리는 세 포털 각각의 규모를 고려해 과설계하지 않는다 - React 기본 상태(useState/
   useContext) + 서버 데이터는 캐싱 라이브러리(예: TanStack Query류) 정도로 충분하다.
   전역 상태 라이브러리(Redux 등) 도입은 실제 필요가 드러나기 전까지 보류.
3. 시각적 완성도(타이포그래피/애니메이션/트랜지션)와 인터랙티브함(즉각적 상태 반영,
   로딩/에러 상태 처리) 둘 다 "최고 수준"이 목표임을 화면 구현 시 기준으로 삼는다 -
   정적으로 예쁘기만 한 화면이 아니라, 조작했을 때 반응이 매끄러운 것까지 완성 기준에
   포함한다.

## 2. 배포/도메인 구조 (확정)

### 2.1 기존 서비스는 그대로 유지 (절대 원칙, v1/v2와 동일)
- 기존 운영 서비스(`www.artready.kr`, Vercel 프로젝트 `artready-gamma`)는 **전혀 건드리지
  않는다.** 코드·배포 경로·도메인 전부 이번 작업과 100% 분리.
- 기존 서비스는 회원가입 없는 무료 공개 지식그래프 서비스(대학찾기/성적추천/입시Q&A)로,
  신규 B2B 플랫폼의 "무료 유입 채널" 역할을 겸한다 - 신규 플랫폼과 목적·고객층이 다르다.

### 2.2 신규 Vercel 프로젝트 3개 분리 생성
동일 GitHub 저장소를 Root Directory만 다르게 지정해 독립 프로젝트 3개로 배포한다:

| 프로젝트 | Root Directory | 서브도메인 | 용도 |
|---|---|---|---|
| `artready-b2b-bo` | `franchise/web/bo`(빌드 후 산출물) | `admin.artready.kr` | 엔코아 본사 통합 관리자 |
| `artready-b2b-co` | `franchise/web/co`(빌드 후 산출물) | `partner.artready.kr` | 가맹 학원 원장·강사 |
| `artready-b2b-fo` | `franchise/web/fo`(빌드 후 산출물) | `app.artready.kr` | 학생·학부모 |

- 서브도메인은 `artready.kr` 최상위 도메인 아래 신규 DNS 레코드만 추가하는 것이라
  기존 `www` 레코드에는 영향이 없다.
- React+Vite 전환 후에도 각 포털은 여전히 **독립적으로 빌드/배포**되는 별도 프로젝트로
  유지한다(하나의 모노 SPA로 합치지 않는다) - BO/CO/FO는 권한 경계가 다른 별도
  애플리케이션이라는 원칙(v2.0 2절)과 일치시키기 위함이다.

### 2.3 기존 사이트 ↔ FO 연동 (참고, 이번 단계 필수 아님)
향후 `www.artready.kr`에 "로그인" 버튼을 추가해 `app.artready.kr`(FO)로 연결하는 안을
검토 중이다. 이건 기존 사이트 쪽에 링크 하나 추가하는 수준의 경량 작업이라 이번 프론트엔드
전환과는 별개로 나중에 처리한다. **문구는 "누구나 로그인 가능"처럼 오해되지 않도록
"계약 학원 소속 학생/학부모만 로그인 가능"이라는 취지를 담을 것.**
