## 0. 지금 상황 — 프로덕션이 100% 작동 불능이다

v5.0 완료 보고("ALL PASS")를 실제로 검수한 결과, **지금 라이브로 배포된 BO/CO/FO
3개 사이트는 화면만 뜨고 버튼을 누르면 전부 실패한다.** 구체적으로:

1. **배포된 프론트엔드 3개 전부(BO/CO/FO) JS 번들 안에 `http://localhost:8000`이
   하드코딩돼 있다.** 실제 방문자가 어떤 버튼을 눌러도 그 사람 브라우저가 자기 PC의
   localhost:8000에 접속을 시도하다가 100% 실패한다. **아무 기능도 동작하지 않는다.**
2. `test_api.py`의 "16/16 PASS"는 `fastapi.testclient.TestClient`를 쓴 것이다 -
   이건 네트워크도, 배포도 없이 파이썬 코드 안에서 함수를 직접 호출하는 것이다.
   **실제 서버조차 띄우지 않고 "배포 검증 완료"라고 보고한 것**이다.
3. 성적기록함/서류함 데이터는 `GRADE_RECORDS_DB = [...]`라는 **파이썬 리스트
   변수**에 저장된다. Supabase 호출은 0건이다. 서버 프로세스가 재시작되면(서버리스
   환경에서는 요청마다 그럴 수 있음) 데이터가 통째로 사라진다. "성적이 바뀌니
   이력으로 남긴다"는 이 기능의 존재 이유 자체가 성립하지 않는다.

**이 세 가지는 전부 "화면에 메뉴가 있다"/"코드에 그 단어가 있다"는 얕은 확인으로는
절대 못 잡는다.** 지금부터는 아래 1절의 검증 절차를 예외 없이 따른다.

## 1. "완료"로 인정하는 유일한 기준 (Definition of Done)

아래 6가지를 **전부, 실제로, 지금 당장** 만족시켜라. 하나라도 빠지면 반려한다.

1. **백엔드를 실제 URL로 배포한다.** `localhost`, `127.0.0.1`이 아닌, 인터넷 어디서든
   접속되는 진짜 URL. `curl https://<그 URL>/health`를 **회사 컴퓨터가 아닌 곳에서도
   실행 가능한 형태로** 보고서에 제시할 것.
2. **프론트엔드 3개(BO/CO/FO)를 그 실제 URL을 가리키도록 다시 빌드하고 재배포한다.**
   재배포 후 `curl https://adminartreadykr.vercel.app/assets/<번들>.js | grep localhost`
   결과가 **반드시 0건(아무 것도 안 나옴)**이어야 한다. 이 curl 결과를 그대로 보고서에 붙여라.
3. **모든 데이터는 Supabase 테이블에 실제로 저장한다.** 인메모리 리스트/딕셔너리
   금지. `franchise/schema/`의 기존 스키마와 `02_v5_schema_extension.sql`을 실제로
   Supabase에 마이그레이션 적용하고, 백엔드 코드는 그 테이블에 INSERT/SELECT/UPDATE/
   DELETE 하도록 작성한다.
4. **영속성(persistence) 자체를 증명하는 시나리오 1개를 실행하고 캡처한다**: 예)
   BO 화면에서 신규 가맹학원을 등록 → 브라우저 새로고침(F5) → 방금 등록한 학원이
   여전히 목록에 보임. 이걸 스크린샷 2장(등록 직후 / 새로고침 후)으로 증명할 것.
   새로고침 후 사라지면 실패다.
5. **27개 메뉴 전부에 대해, 배포된 실제 URL을 대상으로 한 curl 재현 결과**를 첨부한다.
   `TestClient`나 로컬 실행 결과는 증거로 인정하지 않는다. 반드시 `https://` 로 시작하는
   실제 도메인에 대한 curl이어야 한다.
6. **`franchise/api` 프로세스가 죽었다가 다시 켜져도(또는 다른 서버리스 인스턴스가
   요청을 받아도) 데이터가 그대로인지** 확인한다 - 이게 안 되면 3번(인메모리 금지)이
   지켜지지 않은 것이다.

## 2. 이번엔 증거로 인정하지 않는 것 (반복 방지)

- 코드에 특정 단어/함수명이 존재한다는 grep 결과
- `fastapi.testclient.TestClient` 또는 이와 동급의 인프로세스 테스트 결과
- JS 번들 안에 특정 문자열이 있다는 것만으로 "기능이 동작한다"고 주장하는 것
- `localhost`/`127.0.0.1`을 가리키는 그 어떤 것도 "배포 완료"의 증거가 될 수 없다
