# GDS 투영·중심성: 환경 구축 가이드

이 문서는 **실습 환경을 만드는 것**까지만 다룹니다. 무엇을 배우는지는 노트북 안에 있습니다.

## 무엇이 들어 있나

| 파일 | 내용 |
|---|---|
| `교안_01_GDS_투영_차수.ipynb` | GDS 엔진, 그래프 투영, 담는 범위, 방향, 투영 관리, 차수 |
| `교안_02_중심성_PageRank.ipynb` | PageRank·매개·근접 중심성, 실행 모드, 개인화 PageRank |

중간부터 열어도 됩니다.

## 1. Neo4j: 실습 전용 데이터베이스

> **반드시 "실습 전용" 데이터베이스에 연결하세요.** 모든 노트북이 서두에서 그래프를 **모두 지우고**
> 새로 만들며, 메모리에 남은 **투영도 전부 정리**합니다.

- 지난 그래프DB 단원에서 설치한 자기 로컬 Neo4j 를 씁니다(`bolt://localhost:7687`).
- 접속 정보는 **`.env` 로만** 바꿉니다. 노트북에 포트·비밀번호를 적지 마세요.

## 2. GDS 플러그인 켜기

이 단원은 GDS(Graph Data Science) 없이는 한 셀도 돌아가지 않습니다.

- **내 컴퓨터의 Neo4j**: Neo4j Desktop 에서 실습 DBMS 를 고르고
  **Plugins → Graph Data Science Library → Install** 을 누른 뒤 **Restart** 합니다.
- **Aura**: 플러그인을 직접 설치하지 않습니다. 대신 **Aura Graph Analytics** 세션이 같은 알고리즘을
  돌려 줍니다(무료 등급도 과금 없이 열리며 한 번에 세션 하나, 메모리 2GB, 최대 4시간).
- 어느 쪽이든 확인은 교안_01 의 `gds.version()` 셀로 합니다. 버전 문자열이 찍히면 준비된 것입니다.

## 3. 파이썬 환경

터미널에서 아래를 실행합니다(환경 구축도 실습의 일부입니다).

```bash
uv add jupyter neo4j python-dotenv pandas   # day33 (jupyter 안에 VS Code 커널용 ipykernel 포함)
```

- VS Code 로 노트북을 열고 커널로 **Python 3 (ipykernel)**(= 방금 만든 `.venv`)를 고릅니다.
- `.env.example` 을 `.env` 로 복사해 `NEO4J_URI`·`NEO4J_USER`·`NEO4J_PASSWORD` 를 채웁니다.

## 환경이 말썽일 때

- **Neo4j 연결이 안 된다**: DB 가 켜져 있는지, `.env` 의 주소·계정이 맞는지 확인합니다.
- **`Unknown function 'gds.version'`**: GDS 플러그인이 아직 안 켜졌습니다. 설치한 뒤 **재시작**했는지
  확인하세요.
- **`graph already exists`**: 같은 이름의 투영이 메모리에 남아 있습니다. 노트북 맨 위 **제공 코드 셀
  셋(연결·초기화·적재)** 을 위에서부터 다시 실행하세요. 초기화 셀만 돌리면 데이터까지 지워져 빈 DB 가 됩니다.
- **`Graph with name ... does not exist`**: 만들어 둔 투영이 사라진 것입니다. 투영은 노트북이 아니라
  **Neo4j 서버 메모리**에 있어서 같은 DB 에 붙은 다른 노트북이 초기화 셀을 돌리면 함께 지워집니다.
  **노트북은 한 번에 하나만 열어 두고**, 이 에러를 만나면 그 투영을 만든 셀부터 다시 실행하세요.
- **초기화 셀이 "이 단원 것이 아닌 노드가 있습니다" 라며 멈춘다**: 지우기 전에 DB 를 확인하는
  가드입니다. `.env` 의 `NEO4J_URI` 가 실습 전용 DB 를 가리키는지 먼저 보세요.
- 코드가 막히면 답안 셀의 **힌트**를 펼쳐 보고, 그래도 막히면 `정답/` 노트북의 해설과 비교합니다.
