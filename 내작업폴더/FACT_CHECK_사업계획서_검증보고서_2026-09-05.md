**작성일**: 2026-09-05
**검증 대상**: 다른 에이전트(Antigravity)가 작성한 `dart_business_plan_and_test_scenarios.md`
**검증 방법**: 코드 직접 읽기(grep/read) + 운영 Neo4j Aura 클라우드 라이브 쿼리 실측 대조. 문서의 주장을 단 하나도 그대로 믿지 않고 전수 재확인.
**결론 요약**: 인프라 수치(노드/관계/승격 지분/자본이벤트 건수)는 100% 정확함. 그러나 **가장 화려하게 홍보된 차별화 기능 3가지(GDS PageRank/Betweenness/Degree, Hop 슬라이더, 순환출자 자동탐지, 삼성/현대차 등 대기업집단 시연)는 코드에 존재하지 않거나 데이터가 텅 비어 있어 실제로 재현 불가능**함. 사업계획서를 이 상태로 고객에게 시연하면 첫 데모에서 바로 거짓말이 들통난다.

## 2. ❌ 과장·허위·재현 불가로 확인된 항목 (Confirmed FALSE / Misleading)

### 2-1. "GDS 알고리즘 메모리 프로젝션 실행" / "PageRank" / "Betweenness(매개 중심성)" / "Degree(연결 중심성)" — **전부 미구현**

`app_dart_trace_dashboard.py:1587-1715` (메뉴3 "GDS 재계 권력 랭킹") 코드를 직접 읽었습니다.

- 실제 랭킹은 다음의 **단순 Cypher 카운트 쿼리 하나**로 계산됩니다:
  ```cypher
  MATCH (h:DART_Company)-[r:HOLDS_ECONOMIC_STAKE]->(t:DART_Company)
  OPTIONAL MATCH (t)-[sub_r:HOLDS_ECONOMIC_STAKE]->(sub_t:DART_Company)
  ... count(DISTINCT t) + count(DISTINCT sub_t) ... ORDER BY 총지배기업수 DESC
  ```
  이건 "직접+2단계 우회 계열사 개수 세기"이지, PageRank(재귀적 가중치 전파), Betweenness(최단경로 경유 빈도), Degree(연결 중심성) **어느 것도 아닙니다.**
- 코드 전체에서 `gds.pageRank`, `gds.betweenness`, `gds.degree`, `gds.graph.project` 등 **실제 GDS 프로시저 호출은 단 한 번도 없습니다** (grep 전수 확인).
- "🧠 GDS 알고리즘 원리" 패널(1704~1715행)은 PageRank/Betweenness가 **개념적으로 무엇인지 설명하는 정적 텍스트 카드**일 뿐, 화면에 표시되는 실제 랭킹 숫자와는 아무 연결이 없습니다.
- GDS 라이브러리 자체는 Aura에 설치돼 있지만(§1 참조), **이 앱은 그걸 한 번도 호출하지 않습니다.**

→ **"Neo4j GDS 알고리즘 메모리 프로젝션 실행", "Betweenness 자금 길목 탐지", "Degree 랭킹 및 필터링"은 사업계획서의 순수 창작이며, 코드에 대응물이 없습니다.** UI에서 "필터링" 기능(알고리즘 전환 선택지)도 존재하지 않습니다.

### 2-2. 시나리오 2 "삼성전자 검색 → Hop 슬라이더 3 → 이재용 노드 드래그" — **3중으로 재현 불가능**

1. **Hop 깊이 슬라이더 자체가 없음**: 메뉴1 코드(`794~980행`) 전수 확인 결과 "탐색 모드"(프리셋/초성색인/Cypher직접입력) 선택지만 있고, Hop depth를 숫자로 조절하는 슬라이더 UI는 **존재하지 않습니다.**
2. **"이재용" 노드가 그래프에 없음**: 라이브 쿼리로 확인한 결과 `DART_Person` 라벨 노드는 **0건**입니다. (이번 세션 초반에 있었던 거버넌스 위반 사고 — 무단으로 생성된 `DART_Person` 485건 + `OWNS_STAKE` 646건을 이미 전량 삭제·정화했기 때문. 이건 의도된 정상 상태입니다.) 즉 사람 노드를 드래그하는 시연 자체가 물리적으로 불가능합니다.
3. **"삼성그룹" 프리셋이 텅 비어 있음**: 메뉴1 드롭다운의 "삼성그룹 (삼각 지배구조 - 내일 대규모 수집 대상)" 옵션은 코드 상 `LIMIT 0`으로 하드코딩돼 있습니다 (`app_dart_trace_dashboard.py:964-969`). "현대자동차그룹", "SK그룹", "LG그룹", "한화그룹", "국민연금"도 전부 동일하게 `LIMIT 0` — **6대 프리셋 전부가 데이터 없는 빈 자리표시자**입니다. 라벨의 "내일 대규모 수집 대상"이라는 문구가 이미 "아직 수집 안 됨"을 스스로 밝히고 있습니다.

→ **사업계획서의 가장 임팩트 있는 데모 시나리오(대기업 지배구조 시각화)가 삼성 기준으로는 100% 실행 불가능**합니다. 지금 수집·승격된 실제 데이터는 롯데그룹/알루코-케이피티유/현대홈쇼핑-현대퓨처넷 등 **소수 케이스뿐**입니다.

### 2-3. "순환출자 루프(A→B→C→A) 자동 탐지 알고리즘" — **미구현**

전체 코드에서 순환 탐지 관련 Cypher(`shortestPath`, cycle 관련 로직 등)를 검색했으나 **전혀 없습니다.** "순환출자"라는 단어는 메뉴 제목과 드롭다운 라벨에 **문자열로만** 등장할 뿐, 실제로 사이클을 탐지해서 강조 표시하는 알고리즘은 존재하지 않습니다.

### 2-4. "특정 총수 → 타깃 기업 최단 지배 경로 하이라이트" — **미구현**

`shortestPath()` Cypher 함수 사용처가 전체 코드에 없습니다. 최단 경로 계산·하이라이트 기능은 존재하지 않습니다.

### 2-5. 화면 내 통계 수치 자기모순 (신뢰도 훼손 리스크)

- 메뉴2 챗봇 안내문(1514행): "15,000건 공시 원문 증거(23,996건 후보)"
- 메뉴6 탭 라벨(1975행): "1,500건 전수"
- 실측 라이브 `RawEvidenceCandidate` 카운트: **27,208건**

세 곳 모두 다른 숫자가 하드코딩되어 있고, 그 어느 것도 실제 라이브 값(27,208)과 일치하지 않습니다. 사용자가 화면 두 곳만 번갈아 봐도 "어느 숫자가 진짜냐"는 의문이 바로 생깁니다.

## 3. ⚠️ 검증 불가/판단 보류 항목

- **B2C/B2B/B2G 가격 정책, 시장 규모, 매출 모델**: 이건 코드로 검증할 수 있는 '사실'이 아니라 사업 전략 제안입니다. 옳고 그름의 문제가 아니라 "우리가 합의했는지"의 문제이므로 별도로 논의가 필요합니다.

## 4. 진짜 좋은 모델로 가려면: 방향 제안

솔직하게 말씀드리면, 이 프로젝트의 **진짜 차별화는 이미 갖고 있는 것**입니다 — "PageRank/Betweenness" 같은 있어 보이는 알고리즘 이름이 아니라:

> **"금감원 원문 행(Row) 단위 SHA-256 해시로 결속된, 거짓 없는 경제적 지분 사실 1,696건 + `OWNS_STAKE` 0건 유지라는 거버넌스 원칙"**

이게 네이버 증권도, ChatGPT도 못 하는 진짜 유일한 무기입니다. 그런데 지금 사업계획서는 이 진짜 무기 대신 **없는 기능(GDS/이재용 드래그/순환출자 탐지)을 자랑하는 데 지면을 다 씁니다.** 이대로 고객 앞에서 시연하면 "삼성전자 검색해보세요"라는 말이 나오는 순간 신뢰가 무너집니다.

제안하는 우선순위:

1. **(최우선, 정직성 회복)** 메뉴3을 "PageRank/GDS/Betweenness"라고 부르지 말고, 있는 그대로 "**승격 지분 관계 기반 지배 계열사 수 랭킹**"으로 정직하게 재명명하거나 — 정말 원한다면 실제 `gds.pageRank.stream()`을 붙여서 이름값을 하게 만들거나. 저는 전자(정직한 재명명)를 권합니다. 가짜 알고리즘 브랜딩보다 "우리는 절대 거짓 지분율을 안 만든다"는 포지셔닝이 훨씬 강력합니다.
2. **(데모 리스크 제거)** 사업계획서의 시연 시나리오에서 삼성/현대차/SK/LG/한화 등 **미수집 대기업집단을 즉시 빼고**, 실제 데이터가 있는 롯데/알루코/현대홈쇼핑 케이스로 교체.
3. **(신뢰도)** 화면 곳곳에 흩어진 하드코딩 통계 문자열(15,000/23,996/1,500건 등)을 실시간 라이브 카운트 쿼리로 통일 — 이미 메뉴6은 이렇게 하고 있으니 그 패턴을 나머지 화면에도 적용.
4. **(선택)** Hop 슬라이더·순환출자 자동탐지·최단경로 하이라이트는 사업계획서가 약속한 만큼 "고객이 만져보고 싶어할 기능"이긴 합니다 — 다만 지금은 **없는 걸 있다고 말하지 않는 것**이 먼저이고, 이건 그다음 개발 우선순위로 논의하시죠.
