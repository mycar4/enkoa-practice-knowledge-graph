# 🏫 ART:READY 프랜차이즈 B2B 플랫폼 — Antigravity 작업지시서 (v4.0, 전체 메뉴·기능 재정리)

> **작성일**: 2026-09-19
> **작성자**: Claude (프로젝트 - ART:READY 지식그래프 서비스 담당)
> **수신**: Antigravity (프랜차이즈/RDB 회원가입 플랫폼 별도 개발 담당)
> **상태**: **전면 재개발 지시.** 1차 산출물(`franchise/web/{bo,co,fo}` 현재 코드)을 검수한 결과
> BO는 메뉴 자체가 없고, CO는 메뉴가 2개뿐이며, 배포도 CO/FO가 Vercel 인증벽에 막혀
> 실제 화면 확인이 불가능한 상태였다. **이 문서가 v1~v3의 모든 요구사항을 하나로
> 통합한 최종 기준**이다 - 이 문서 기준으로 BO/CO/FO를 처음부터 다시 개발한다.
> **v1.0/v2.0/v3.0은 이 문서로 대체되며, 개별 조항이 필요하면 이 문서를 우선 참조할 것.**

---

## 0. 지키지 않으면 다시 반려되는 원칙

1. 실행하지 않은 것을 "완료"라고 쓰지 않는다 - 매 산출물에 실제 배포 URL + 화면 캡처 + 클릭 시나리오 결과 첨부.
2. **배포한 URL은 로그인 없이 외부에서 접속 가능해야 한다** - Vercel "Deployment Protection"을
   꺼서 우리가 직접 화면을 확인할 수 있게 할 것(현재 CO/FO가 이 문제로 검수 자체가 불가능했음).
3. 각 포털의 메뉴는 아래 1~3절에 나열된 것을 **전부** 클릭 가능한 화면으로 구현한다 -
   "예시 데이터만 있는 화면"이어도 좋으니, 메뉴 자체가 없는 상태(현재 BO)는 금지.
4. 수치를 지어내지 않는다. 불확실하면 "확인 필요"로 표시한다.
5. 절대 금지사항(v1.0 동일): 기존 `services/art_admission_*.py`/`api_art_admission.py`/
   최상위 `fo/*.html`/Neo4j/기존 배포 워크플로/기존 Vercel 프로젝트(`artready-gamma`,
   `www.artready.kr`) 손대지 않기.

## 4. 공통(3개 포털 전부 해당) 요건

### 4.1 인증/권한
- 로그인은 이메일 또는 휴대폰 기반, Supabase Auth 사용.
- 권한은 3중 구조: **테넌트(학원) 격리 → 역할(원장/강사/학생/학부모) → 메뉴별 개별 권한**
  (`MENU_PERMISSIONS`). RLS 정책은 `tenant_id`만 확인하는 게 아니라 **개인 단위 join**까지
  확인해야 한다(v2.0 지적사항 - 강사가 미배정 학생을 보거나, 학부모가 남의 자녀를 보는 것 방지).

### 4.2 프론트엔드 기술스택 (v3.0과 동일, 재확인)
- React + Vite. Next.js 사용하지 않음.
- 세 포털 공통 디자인 시스템(색상 토큰/타이포/버튼·카드·모달·폼 컴포넌트)을 먼저 확정하고
  그 위에서 화면을 조립한다. BO의 기존 다크테마 토큰(`--bg-main:#0b1120`,
  `--primary:#6366f1` 등)은 나쁘지 않은 출발점이니 폐기하지 말고 디자인 시스템의
  기반으로 검토할 것 - 단, 이걸 CO/FO에도 일관되게 적용할지는 디자인 시스템 확정 시 같이 정한다.

### 4.3 배포
- 신규 Vercel 프로젝트 3개, Root Directory로 분리, 서브도메인 3개(2.2절 표는 v3.0 참고).
- **모든 배포는 프로덕션 도메인(커스텀 서브도메인)으로 연결하거나, Deployment Protection을
  꺼서 외부 검수가 가능한 상태로 유지한다.**

### 4.4 개인정보/보안 (v2.0 3.9절 동일, 재확인)
- PII 컬럼 암호화(pgcrypto/Supabase Vault), 실기 작품 이미지는 비공개 버킷 + 만료형 서명 URL.
- 회원 탈퇴 시 즉시 비식별화, 결제 기록만 약 5년 보관 후 파기.
