# 🎨 ART:READY(미대입시 챗봇) 작업 가이드 (내작업폴더/CLAUDE.md)

> 루트 `CLAUDE.md`는 DART-Trace(기업지분) 프로젝트 전용이다. 이 파일은
> `내작업폴더/` 아래(art_admission 서비스) 작업 시에만 적용된다.

## 1. 🛡️ 필수 규칙: 버그 수정 = 수정 + 회귀 테스트 (한 커밋)

> **2026-09-23 실측 근거**: 하루 동안 "컨텍스트 좁히기가 근거를 버려 오답이 나오는"
> 같은 유형의 사고가 **3번** 반복됐다(대학 수 6곳→실제 55곳, 소묘 학교 목록이
> 턴마다 바뀜, 홍대 실기 날짜→실제로는 면접일). 세 번 다 "코드만 고치고 넘어갔다".
> 그날 33건 수정 중 테스트가 함께 들어간 건 4건(12%)뿐이었다. day48(리랭킹·
> 컨텍스트 압축)을 배우고 나서야 `narrow_context()`를 순수 함수로 분리해 회귀
> 테스트 6종을 만들었는데, 1번째 사고 때 만들었다면 2·3번째는 배포 전에 잡혔다.

**규칙**: 사용자가 제보한 실제 버그를 고칠 때는, 그 자리에서 재현에 쓴 로컬
스크립트를 **버리지 말고 `내작업폴더/tests/`의 회귀 테스트로 남긴다.** 같은
커밋에 "수정 코드 + 테스트"를 함께 넣는다. LLM 호출이 필요해 무료 게이트에
못 넣는 테스트는 `test_art_admission_rag_eval.py`처럼 로컬 실행용으로라도
파일에 남긴다(다음에 같은 종류의 버그가 의심될 때 바로 돌려볼 수 있게).

**예외**: 순수 UX 문구 변경, 오탈자 수정처럼 "재현 가능한 실패 조건" 자체가
없는 수정은 테스트를 만들지 않아도 된다.

## 2. 프롬프트로 안 되면 코드로 강제한다

시스템 프롬프트에 규칙을 두 번 이상 명시했는데도 gpt-4o-mini가 계속 빠뜨리는
것을 실측으로 확인했다면(예: "실기 종목 알려주면 좁혀준다" 안내 문구), 프롬프트
튜닝을 더 시도하지 말고 **코드로 결정론적으로 강제**한다. "동명 전형 구분",
"대학 수 집계", "실기종목 안내 문구"가 전부 이 패턴으로 해결됐다.

## 3. 배포 전 필수 절차 (순서 고정)

```
1. 로컬 재현(버그 재현 스크립트 또는 위 1번 규칙에 따라 만든 테스트)
2. 수정
3. python 내작업폴더/tests/ci_quality_gate.py  (게이트 통과 확인)
4. git add <수정 파일만> (git add -A 금지)
5. git commit (수정 이유·재현 방법·검증 결과를 커밋 메시지에 구체적으로)
6. git push (GitHub Actions가 자동 배포)
7. gh run list --repo mycar4/enkoa-practice-knowledge-graph
   --workflow=deploy-art-admission-api.yml --limit 1  로 배포 완료 확인
8. 프로덕션(https://api.unsuzone.com/art-admission)에 실제 curl로 재검증
```

## 4. Neo4j 쿼리 정렬 규칙

`list_tracks_with_estimates()`류 검색 기반 함수는 반드시 `ORDER BY`를 명시한다.
Neo4j는 정렬 없는 MATCH의 행 순서를 호출마다 보장하지 않는다 - 2026-09-23
실측으로, ORDER BY 누락이 "같은 질문에 매번 다른 학교 목록"이 나오는 근본
원인이었음을 확인했다(search_tracks가 상위 20건만 자르는데 그 20건이 호출마다
달라짐).

## 5. 컨텍스트 좁히기(압축) 작업 시 필수 확인

LLM에 넣기 전 컨텍스트를 좁히는 코드를 건드릴 때는 반드시:
- `내작업폴더/tests/test_art_admission_context_preservation.py`의
  `narrow_context()` 테스트를 먼저 돌려본다.
- 좁히기 전/후로 "일치하는 근거가 하나도 안 사라졌는지"를 확인한다.
- 토큰 절감률이 아니라 **근거 보존 여부**를 우선 기준으로 삼는다
  (`내학습폴더/day48_리랭킹_컨텍스트압축/` 참고 - 압축 후 토큰 86.6% 줄었지만
  답이 오답으로 뒤집힌 실측 사례가 있다).
