## 1. 교안_01: 트리플과 관계 시그니처 (순수 파이썬, Neo4j 불필요)

- [ ] 준비 셀 두 개(모델 / 이름 사전) 실행.

**1. 논문 문장을 트리플로**

- [ ] **1. 논문 문장을 트리플로**: 논문 문장 하나를 트리플 여러 개로 분해하고, `merge_by_name` 으로 `MERGE` 문 문자열까지. 트리플·LPG·`MERGE` 는 앞 단원에서 배운 것이라 복습으로 눌러 쓰고, **그래프로 옮길 때 타입 두 칸이 더 필요하다**는 것만 새로 짚습니다. 퀴즈 2문.

**2. 온톨로지 설계: 무엇을 허용할 것인가**

- [ ] **2-1 노드의 키: 이름이 아니라 id**: 이름 하나가 두 개체에 걸린 경우 9건을 사전에서 직접 확인, `lookup_id` 로 조회(`(id, 사유)` 두 칸을 돌려주어 `miss` 와 `ambiguous` 를 가른다), 사전에 없으면 `:Candidate` 로 격리, id 를 키로 MERGE 문을 만드는 `triple_to_cypher`. 따라하기(붙는 것/후보 가르기)·퀴즈 2문.
- [ ] **2-2 관계 시그니처: 주어 타입·목적어 타입·판정 기준**: `RELATION_SIGNATURES` 8종(주어타입·목적어타입·판정기준·건수). 그래프의 관계 12종 중 8종을 골라 씁니다.
      - **핵심 판정 하나**: `TREATS`(755건) 와 `PALLIATES`(390건) 는 타입이 같아 판정 기준으로만 갈린다.
      - **핵심 판정 둘**: 대사·수송 진술도 `BINDS` 로 적는다. 그 대가로 표적·효소·수송체가 한 관계로 뭉개진다. **온톨로지가 구분하지 않기로 한 것은 나중에 되찾을 수 없다.**
      - 따라하기 두 번(관계 한 줄 더하기 / 트리플 리스트를 하나의 Cypher 스크립트로 `triples_to_script`)·퀴즈 3문.

## 2. 교안_02: 온톨로지·추출·적재 (Neo4j + 모델)

- [ ] 준비 셀 → Neo4j 연결 셀 → **그래프 초기화 셀** → 이름 사전 셀 실행(실습 전용 DB 확인!).

**1. 규격 정하기: 온톨로지와 트리플 서식**

- [ ] **1-1 온톨로지: 하나의 계약**: 시그니처 dict + `build_ontology_block`(프롬프트 블록 자동 생성). 따라하기(관계 추가)·퀴즈 2문.
- [ ] **1-2 트리플 서식**: 먼저 값 집합을 안 좁힌 `LooseTriple` 로 뽑아 관계 이름이 제멋대로인 것을 확인하고, 그다음 **온톨로지에서 값 집합을 그대로 가져와** `Literal` 로 좁힌 `Triple`·`Extraction` 을 세웁니다(`RELATION_SIGNATURES`·`NODE_TYPES` → JSON Schema 의 `enum`). 서식이 못 보는 것은 **칸 사이의 약속**이라는 것까지. 따라하기(칸 꺼내기)·퀴즈 2문.

**2. 추출 프롬프트 설계**

- [ ] **2-1 온톨로지 주입**: `build_extraction_prompt()` 가 **`ChatPromptTemplate`** 을 돌려주고(system=역할+온톨로지+규칙, human=`{text}`), `템플릿 | 모델` 로 이어 붙여 `invoke({"text": ...})` 로 호출합니다. 규칙 네 줄에 **"맞는 관계가 없으면 넣지 않는다"** 가 들어갑니다(서식이 값을 좁혔으니 빠져나갈 곳을 규칙이 열어 준다). 근거(evidence)는 **문장 하나를 통째로** 옮기게 합니다(200자 제한을 걸면 모델이 줄임표로 이어 붙여 3-1 근거 검사에 무더기로 걸립니다). **`BINDS` 판정 기준 한 줄이 대사 진술의 갈 곳을 정해 주는 것**과, 그 대가로 효소·수송체·표적이 한 관계로 뭉개지는 것을 데모 결과에서 확인. 따라하기(다른 논문 발췌로 추출, 시그니처 위반 찾기)·퀴즈 2문.
- [ ] **2-2 CoT 로 추출을 단계로 쪼개기**: `reasoning` 칸을 `triples` 앞에 둔 `CoTExtraction`(단계마다 **판정 이유**까지 적게 합니다), `build_cot_prompt()`. 2-1 템플릿과 **다른 곳은 `[생각 순서]` 하나뿐**이라 결과 차이를 CoT 로 돌릴 수 있습니다. 데모 문서에서는 결과가 그대로입니다(CoT 가 늘 이득은 아니다). 어느 단계에서 잃었는지는 `reasoning` 으로 짚습니다. 따라하기(모델을 `gpt-4o-mini` 로 바꿔 같은 프롬프트를 일반·CoT 로 견주기)·퀴즈 3문.

**3. 그래프에 쌓기**

- [ ] **3-1 적재: 이름이 아니라 id 로**: **후처리**(`ground_check` 로 근거가 원문에 있는지·그 근거가 이 트리플을 뒷받침하는지, `drop_duplicates` 로 중복 제거) → `check_signature`(방향까지 대조) → `node_pattern`(id 또는 `:Candidate`) → `load_triple`(값은 파라미터로). 논문 두 편을 더 넣어 **세 검사가 한 문서에서 같이** 일하는 것을 봅니다(`PALLIATES` 의 목적어를 `Symptom` 으로 뽑은 트리플이 기각되고, 약효 분류 이름은 사전에 없어 격리됩니다). 두 편은 `chain.batch([...], config={"max_concurrency": 2})` 로 **한 번에** 뽑습니다(결과는 입력 순서 그대로, 요청은 두 개씩). 적재·기각·격리 건수는 추출 결과에 달려 실행마다 다르므로, 건수가 아니라 **걸리는 갈래**(타입 어긋남 / 사전에 없음)를 봅니다. 못 붙은 이름이 왜 못 붙었는지 **네 갈래**로 가릅니다. 따라하기(후보가 낀 관계 세기)·퀴즈 2문.
- [ ] **3-2 근거 등급: 이 사실은 어디서 왔는가**: `evidence_level`(`curated`/`reported`), 큐레이션 시드 적재, `coalesce` 로 등급을 낮추지 않기, Carbidopa 두 줄 비교. 따라하기(TREATS·PALLIATES 갈라 조회)·퀴즈 2문.
- [ ] **3-3 타입 계층 얹기**: `TYPE_HIERARCHY`·`labels_for`·`set_labels` 로 `:Gene:Enzyme` 겹친 레이블. **2-1 에서 `BINDS` 로 잃은 구분을 노드 쪽에서 일부 되찾고**, 무엇까지는 못 되찾는지도 확인합니다. 따라하기(수송체)·퀴즈 2문.

(대단원 셋을 마친 뒤)

- [ ] **🚀 종합 클론코딩**: 오늘 만든 조각을 전부 이어 붙입니다. 배치 추출→후처리→시그니처 검사→id 해소·적재를 `extract_and_load_batch(rows)` 하나로 묶습니다. 모델 호출은 `batch`(+`max_concurrency`)로 묶고 검사·적재는 문서마다 돌려, 나머지 논문 **세 편**의 문서별 (적재, 근거 미달, 기각, 격리) 네 수를 셉니다(마치면 오늘 쓴 논문 여섯 편이 전부 그래프에 들어갑니다).

## 막혔을 때

- 답안 셀의 **힌트**(접근방법·세부구현)를 먼저 펼쳐 본다.
- 그래도 막히면 **정답 노트북**(`정답/`)의 모범답안·해설과 비교한다.
- 모델 답의 **문구는 매번 달라도 정상**입니다. 자가채점은 구조·개체 포함·건수 범위 같은 **정제된 결과**만 봅니다.
- Neo4j 연결이 안 되면(`ServiceUnavailable`·`AuthError` 등), 1) 데이터베이스가 켜져 있는지 2) `.env` 의 `NEO4J_URI`/`NEO4J_USER`/`NEO4J_PASSWORD` 가 자기 실습 전용 DB 를 가리키는지 확인한다.
- **결과가 교재에 적힌 것과 다르면**, 먼저 프롬프트를 지시한 그대로 만들었는지 보세요. 그리고 이 단원의 추출은 LLM 이 하는 일이라 **같은 프롬프트로도 돌릴 때마다 조금씩 달라집니다.** 교재의 수치는 방향을 보라고 적어 둔 것이지 맞춰야 할 정답이 아닙니다.
- 이름이 사전에 안 붙어 `:Candidate` 가 많이 나와도 **틀린 게 아닙니다.** 사전이 2016년 시점이고 논문이 약어를 많이 쓰기 때문입니다. 그 후보를 어떻게 붙일지는 다음 단원들에서 다룹니다.
